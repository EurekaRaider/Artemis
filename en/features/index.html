A complete working surface

Everything the task needs, without losing the thread.

Artemis brings durable task context, execution tools, review, and extensions into one local desktop workspace.

01

Persistent tasks

Work survives the gap between prompts.

Projects and temporary tasks keep their own event history and working context, so you can return to the task instead of reconstructing it.

  • Project-scoped local checkout
  • Versioned persisted events
  • Temporary tasks when permanence is unnecessary
02

Plan · Execute · Review

The mode defines the boundary.

Plan and Review deny writes before an executor or filesystem call can run. Execute is the mode that exposes execution-capable tools.

  • Read-only Plan and Review
  • Execution surfaces only in Execute
  • Visible mode at the task composer
03

Git-native Review

Review the change where the work happened.

Inspect repository changes and move into commit or push workflows from the same task environment, without separating evidence from implementation.

  • Workspace-aware diffs
  • Branch destination controls
  • Confirmation before publishing actions
04

Terminal and Browser

Use the tools work already depends on.

The integrated Terminal runs as the current desktop user and never auto-elevates. The embedded Browser supports the web while keeping Node, preload APIs, and local files out.

  • User-opened local Terminal
  • HTTP and HTTPS Browser
  • No renderer access to Electron main or Node APIs
05

Plugins · Skills · MCP

Extend capability without hiding the source.

Discover, inspect, and manage integrations from a dedicated resource center, with trust and sandbox controls applied according to capability type.

  • Bundled and local plugins
  • Reusable workflow Skills
  • Per-server MCP controls
06

Automations and Memory

Continue useful work, keep memory bounded.

Recurring tasks can wake up intentionally. Experiential memory stays project-first, validated, and lower priority than the current request and system policy.

  • Recurring task workflows
  • Project-first experiential memory
  • No secrets or transient task state in memory
