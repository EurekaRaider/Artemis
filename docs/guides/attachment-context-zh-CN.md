# 附件上下文保护

Artemis 每条消息最多接受 20 张图片和 10 份文档。每张原始图片不超过 10 MiB，每份文档不超过 100 MiB，原始文件合计不超过 200 MiB。输入框检查累计选择，宿主在绑定到任务时再次检查已保存的字节数。IM 传输仍受渠道和 Gateway 现有限制约束。

原始文件存放在应用私有的 `attachments` 目录。草稿、检查点和来源事件保存引用。旧版本已经提取的文本仍可导入，但历史附件无法恢复旧版本丢弃的格式。Fork 任务保留附件所有权，删除一个任务不会删除其他 fork 的原件。

PDF 和 Office 解析在主进程之外运行，并发 worker 数为 2，单次操作期限为 60 秒。原有 ZIP 展开限制继续生效。解析失败时保留原件并显示失败状态。该流程不涉及云端上传、自动 OCR、向量数据库或额外的 agent 循环。

Plan、Work 和 Codemode 中的 `attachment_list`、`attachment_read`、`attachment_search` 使用宿主代理和当前任务的附件范围。IM 范围还包含当前授权上下文。读取返回有界文本、来源位置和续读偏移量。PDF 页面可按需渲染；图片裁剪采用原图坐标。桌面原件预览与模型使用的图片副本相互独立。

提示词图片保留宽高比和透明度、不放大，并同时满足最长边 2048 像素及 2500 个 patch（每个 32×32 像素）的预算。原生解码前先检查文件头，拒绝超过一亿像素的图片。即使下一次请求只能容纳部分图片，所有已接受图片仍可检索。

小文档只有在内容完整且剩余预算允许时才注入上下文，上限为估计 8000 token 与模型窗口 5% 两者中的较小值。单次文本读取采用保守的 4000-token 上限。文本估算基于 UTF-8 字节，避免低估中文和密集数据；图片估算按提供商保守计算，不是提供商报告的用量。

最终模型请求用 Pi 的字符/token 启发式估计普通文本，同时计入保守图片估算、输出预留和安全余量。UTF-8 字节上限用于附件提取，不用于整段会话。请求视图可省略可替换的附件图片，同时保留检索引用；普通用户文本绝不静默截断。本地超限错误包含估计输入和可用预算，并进入 Pi 现有的单次压缩后重试恢复流程。估计值不是提供商 token 计数。

手动和自动压缩共用有界摘要流。过大的摘要输入按序列化消息／行边界切分，必要时切分单个过大结果，分别摘要后与 Pi 原始摘要指令合并。只有完整摘要才交回 Pi 持久化。失败或取消时保留历史，时间线如实显示，不显示为压缩成功。切换模型时按新模型重算预算，不丢弃历史。若固定摘要指令本身无法容纳，需缩短指令或使用更大的模型窗口。

输入框默认显示单行 34 像素附件摘要，最多包含 3 张缩略图及汇总处理状态。展开后显示有序列表，滚动区域上限为 160 像素，支持原图预览、单项删除和清空。Escape 收起列表或关闭预览。

为附件摘要、有界列表和原生预览对话框，桌面 CSS 门禁从 371,000 字节提高到 374,000 字节。该次测量的生产 CSS 为 372,904 字节；其他性能阈值保持不变。
