# 多语言维护

应用支持英语、简体中文、繁体中文、日语、韩语、西班牙语、法语、德语、巴西葡萄牙语、意大利语、俄语、阿拉伯语、印地语和印尼语。以简体中文和实际产品行为为语义基准，修改可见文案时同步维护所有语言。

## 内容与实现约定

- 可见文案进入按语言索引的资源；共享词条与页面词条分开维护，避免同名键覆盖不同语义。不要重新引入页面内中英分支或英语缺词回退。
- 动态数据使用占位符，保持各语言的键、空值约束、占位符及命令参数一致。
- 用户输入、项目名、文件名、外部插件元数据和原始技术诊断保持原内容。未知技术错误不应伪装成已经翻译的产品结论。
- 日期、星期、数字和时长按当前语言格式化。阿拉伯语界面验证 RTL 和双向插值隔离；复制命令时不得带入仅用于显示的方向控制字符。
- 自动任务标题保留旧版本标题识别；切换语言应刷新附件、归档等已打开界面。
- 安全与权限文案必须与实际模式、范围、信任和系统沙箱一致，不用“完全访问”等笼统说法代替具体边界。

## 验证要求

类型和资源检查覆盖全部语言的键、占位符及技术标识；交互检查覆盖语言切换、命令复制、设置表单、长文本换行和 RTL。原生窗口检查同时记录主题、语言、窗口尺寸、源码版本和数据来源。

2026-09-16 的历史验收覆盖 14 种语言的归档页及德语、阿拉伯语等代表性设置/自动化页面，共 20 个 macOS 开发构建场景。该记录不等于后续新增文案已完成母语审核，也不代表 Windows 原生窗口和最终安装包验收。

仍需持续补充逐语言母语人工审核、Windows 原生视觉检查及发布包验证。旧审计中的临时截图已经失效；新证据应带可追溯的 manifest，不能把 `/tmp` 链接当作长期附件。
