# Pi 1.0.2 与 Artemis 任务模式

Artemis 只使用 Pi 作为 Agent 循环。新任务默认进入 **Work**。

| 模式     | 工具与完成方式                                                                                                  |
| -------- | --------------------------------------------------------------------------------------------------------------- |
| Plan     | 只读调查、讨论和审核。主 Agent 以 `submit_plan` 结束，完整计划等待用户确认。                                    |
| Work     | 直接调用已批准的业务工具。                                                                                      |
| Codemode | 使用 Pi 官方 Codemode 扩展，以 JavaScript 编排业务工具。提问、计划、目标和 Agent 生命周期控制仍由模型直接调用。 |

输入区模式选择器、Slash 菜单点击、键盘选择以及输入 `/plan`、`/work`、`/codemode` 使用同一套模式切换。`/execute` 与 `/review` 已移除；审核仍是任务能力，也可在 Git 差异面板使用。模式在当前轮次结束或取消后切换；携带新要求提交 `/plan` 会取消当前轮次并开始修订。

## 计划确认

计划卡片在会话中保留标题与完整 Markdown，包括目标、步骤、接口变更、验收标准和已达成一致的假设。确认沿用普通提问的选项列表和回复字段，整合在输入区；计划下方没有独立操作栏。**执行计划**接受当前修订并在同一会话进入 Work；下拉菜单提供 **使用 Codemode 执行**。**补充要求**聚焦输入区，不消耗计划；提交要求后原计划被替代，并请求完整新版本。没有待办事项的审核显示 **无需操作**。

计划以版本化宿主事件存入会话数据库。接受时校验当前修订和成功完成的来源轮次，并在一次 SQLite 事务中提交已接受版本、目标模式和执行检查点。执行提示包含完整已接受正文。重复接受返回原执行轮次；失败、不完整和已被替代的计划不能执行。外观像计划的普通文本不能生成可操作卡片。

没有自动确认倒计时。等待会结束模型运行并释放容量；重新打开会话可恢复卡片。目标、定时任务、传输恢复和进程重启都不能接受计划。已接受请求使用正常检查点恢复；有副作用的脚本须核对已完成或结果不确定的调用，不能重放整个脚本。目标续跑保留 Work 或 Codemode。

## 恢复与兼容

Pi 和独立 Responses 传输会重试空启动、中断流以及缺少服务商终止事件的 EOF。失败的助手尝试会被替换，而此前完成的工具结果仍留在上下文。取消会先释放旧传输再开始新尝试。

数据库迁移 14 在早期 `code/work` 迁移之后，将 `execute` 映射到 `work`，`review` 映射到 `plan`；旧 `code` 不会变成 Codemode。检查点、历史和自动化配置会规范化。只有原始指纹有效的自动化授权才会迁移，无效授权保持禁用。开发和测试无需使用真实用户数据库。远程 IM 权限配置目前明确拒绝 Codemode。

## 模型与 MCP 能力

自定义模型高级 JSON 支持 `samplingParams`、`samplingParamsByThinkingLevel`、`thinkingLevelMap`、`inputLimits`、`promptCache`、`cacheWarming`、`compaction` 和 `virtualRoutes`。示例：

```json
{
  "samplingParams": { "temperature": 0.3 },
  "samplingParamsByThinkingLevel": { "high": { "top_p": 0.9 } },
  "cacheWarming": "idle",
  "compaction": { "reserveTokens": 12000, "keepRecentTokens": 16000 }
}
```

虚拟模型使用有序 `virtualRoutes` 数组，元素为 `{ "providerId", "modelId", "thinkingLevel"? }`。Pi 为新用户请求选择首条路由，续跑时保留最近成功的路由，重试时切换下一条。目标必须是已配置的实体模型。

设置中的 **模型服务商授权**使用各服务商的 Pi API Key/OAuth 流程。它是可选功能，仅在用户点击后开始。回答不进入会话历史；凭据和轮换后的令牌使用操作系统加密存储。原有 API Key 和自定义服务商配置仍可使用。

Work 和 Codemode 为已配置的 Pi 图片／分类服务商暴露 `model_capabilities`、`generate_image` 和 `classify`。Codemode 通过 `tools` 调用，图片显示在工具结果中并可下载。`edit_context` 在 Pi 轮次边界调整此前助手／工具上下文投影，保留原始历史，不能修改用户或系统指令。

MCP 工具在发现后仍受宿主审批和沙箱约束。结构化输出 Schema、结构化结果与命名空间元数据传递给 Pi。桌面 OAuth 支持元数据客户端、issuer 校验和按服务器存储凭据。用户服务器配置支持 `exposure` 与 `toolExposure`；`.pi/mcp.json` 可按 ID／名称限制现有已启用服务器、隐藏工具或调整发现暴露方式。项目文件不能启动新服务器或扩大宿主权限。Plan 不接收 MCP 工具。

Work 和 Codemode 中，本地 MCP 或受信任扩展工具在沙箱拒绝后，可携带新的 `model_approval` 请求 `sandbox_escalation: { justification }`。模型必须说明为何这项确切且经用户授权的操作需要桌面用户访问，以及为何重试不会重复结果不确定的副作用。宿主将提权视为高风险：Agent 批准必须有用户对操作及目标的明确请求；否则普通审批界面只提供单次批准。已保存工具授权、自动化授权、Computer Use 任务授权和权限 Hook 放行均不能授权该提权。审批执行时再次校验当前轮次。Plan、远程 MCP 授权、远程权限配置和扩展信任均不可绕过。

提权 MCP 调用使用新的本地服务器连接，调用后关闭；保留已保存服务器配置与最小或明确转发的环境。原沙箱连接仍可处理后续调用，不能假设其进程内句柄可在临时连接使用。可执行扩展只在该次调用中获得桌面用户访问。两种方式都不授予管理员／root 或操作系统隐私权限。失败不会自动提权，也不会重放整个 Codemode 脚本。

受信任的可执行扩展仍需项目／内容哈希信任，并使用原生沙箱。输出 Schema、命名空间、注解和结构化结果跨沙箱桥传递。终端 UI 渲染器、命令、快捷键与任意生命周期处理器不在桌面沙箱工具桥范围内；Artemis 报告不支持的扩展接口，不会在主进程运行它们。

## 验证边界

自动化覆盖包括真实 Pi 循环、真实本地 HTTP socket reset/EOF、已完成工具保留、计划持久化／接受、过期修订、重复点击、迁移、模型路由和加密凭据更新。桌面交互测试使用隔离用户目录、本地模型 fixture 和普通免激活启动。真实服务商 OAuth、付费模型操作、物理 Wi-Fi 断开、Windows 打包与 macOS 发行签名／公证需要各自环境，不包含在这些检查中。
