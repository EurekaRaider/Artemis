# Office 工作台与共享能力包

当前分支包含协议、宿主管理器、原生桥接和预览工作台。Office Runtime 1.0.0 的 macOS arm64 包已独立发布到 [ArtemisRelease](https://github.com/EurekaRaider/ArtemisRelease/releases/tag/office-runtime-v1.0.0)，可信目录已接入本分支和独立测试宿主。公开客户端 v1.6.8 尚未包含此入口，需要后续客户端发布才能向正式版用户开放。原生兼容性门槛和剩余工作见[验收记录](../../projects/office-workbench/README.md)；完整复杂格式保真尚未放行，生产入口仍禁止原生引擎覆盖原文件。

本次平台验收范围为 macOS arm64 与 Windows x64；macOS x64 已按用户要求排除。

## 插件与能力包的关系

Documents、Presentations、Spreadsheets 保留原来的插件身份和入口，共同声明可选的 `office-core` 依赖。安装能力包后，这三个插件使用同一个增强引擎；不会增加三份增强版插件。能力包由宿主管理，轻量插件安装器不执行 `npm install`，也不提高普通插件的归档限额。

未安装能力包时继续提供 Office v1 Lite 工具。Lite 的写入只允许修改由该工具创建、且内容摘要仍匹配的文件；外部导入、外部修改，以及没有来源记录的旧文件不能经简化模型重建后覆盖原件。读取与导出仍保留。来源记录放在宿主用户数据目录，不写入用户文档。

能力包管理入口挂在原插件卡片中。未安装时显示升级图标和“升级 Office 功能”，提供在线安装与单文件离线导入；安装后，三个插件的入口和面板标题同步改为设置图标及“管理 Office 配置”，主操作改为“检查更新”。只在签名校验成功且版本更高时提示明确更新；检查失败不显示“已是最新”，旧目录不会导致降级。离线更新/修复收起在次级入口中。卸载一次即可移除组件、释放空间并让三个插件恢复 Lite，用户文档保留；可选的插件依赖不会阻止显式卸载。正在使用的版本仍由进程内租约保护，界面提示先关闭使用 Office 功能的文档。未配置在线源时显示明确原因。

## 信任与安装

`packages/protocol/src/capability-pack.ts` 定义 `office-core` 签名清单：版本、宿主范围、系统/架构、固定 Release URL、压缩和展开字节数、归档摘要、逐文件清单、原生程序位置与发布者身份。签名使用 Ed25519，信任根来自随宿主发布的目录；离线包不能自行添加可信公钥。

`apps/desktop/resources/office-runtime/catalog.json` 同时固定正式公钥、初始安装清单和 `https://raw.githubusercontent.com/EurekaRaider/ArtemisRelease/main/office-runtime/catalog.json` 更新源。三个插件通过可选的 `office-core` 依赖关联这份宿主目录，不各自下载引擎。远程目录只能提供由宿主已有公钥签名、平台及宿主版本兼容的清单，不能修改公钥或更新 URL。检查更新不触发安装；用户选择新版本后才下载。

正式清单由 `scripts/office/sign-release.mjs` 对已完成平台签名、公证及归档的字节签名。私钥只保存在 Artemis 仓库的 Actions Secret `OFFICE_RUNTIME_ED25519_PRIVATE_KEY`，不进入源码、离线包或公开发布目录。发布时使用 `office-runtime-vX.Y.Z` 独立标签和 `make_latest: false`，逐项读回资产 SHA-256，并保持主程序 Latest 不变。

用户只需选择一个 `.artemis-office` 文件，无需选择 JSON 或解压。其 v1 格式为 8 字节 `ARTOFF1\n`、4 字节大端 JSON 长度、已签名的 JSON 清单及原始运行时 ZIP；清单上限为 16 MiB。容器不改变 ZIP 字节或原生签名，宿主自动验证内嵌清单及载荷，拒绝截断或尾随数据。生成命令：`node scripts/office/create-offline-pack.mjs manifest.json runtime.zip output.artemis-office`。在线安装仍直接使用随宿主发行的可信清单下载和验证 ZIP，无需文件选择。

`CapabilityPackService` 的在线与离线入口共用验证路径：检查签名、平台和宿主版本，限制下载与解压大小，校验归档和文件摘要，拒绝路径穿越、链接及清单外文件，然后按清单执行原生信任检查。Windows 允许清单明确标记未签名的自有 EXE；上游已签名程序仍按各自证书指纹校验。Windows Authenticode 证书不是必需条件，清单的 Ed25519 签名与逐文件摘要仍然必需。临时目录完成后原子切换；同一版本不能更换归档摘要。启动引擎前再次检查完整文件清单。

安装锁以完整记录原子发布，避免并行维护，只回收已确认退出的宿主留下的锁。修复中的版本不能新建租约；在用版本不能被修复替换或卸载。下载取消后清理本次临时目录。损坏收据和内容可从独立验证的原始包重装修复；损坏的激活记录不再被当作可执行安装。Windows 候选包验收脚本逐项检查最终目录的 ACL；异常断电遗留目录的自动清理仍未开放。

## 会话与事件

Pi 仍是唯一模型循环。已有 `office_document` 工具增加 v2 请求，保留 v1；会话操作包括 `open`、`apply`、`snapshot`、`save`、`close`。宿主在构造引擎或读写会话文件前检查 Execute 模式，并继续使用既有模型审批入口。Renderer 仅通过 preload API 与协议类型读取状态和预览。

v2 操作使用预期版本和唯一操作 ID。当前操作支持 Writer 正文、表格和文本框段落，Impress 组内对象及表格单元格文字、对象位移、空幻灯片文字插入，以及 Calc 单元格值和公式。透视表结果区域禁止直接写入；需要修改源数据。SmartArt 文字只接受唯一可定位、段落数不变且无额外缓存文字的修改；其他情况在编辑前拒绝。成功操作先写入恢复日志，再确认并发送版本化 `artifact.event`。保存版本、文档草稿版本和预览版本独立记录；未保存草稿不会标为已落盘。

每个会话保留原文件的独立基线及摘要。引擎中断后重放已提交操作，忽略未确认的操作意图；恢复前校验基线和日志结构。打开路径必须位于任务工作区，同一原文件不能同时归属两个任务。日志和文档大小、会话数量均有上限。

事件使用既有持久化 envelope，reducer 去重并检测缺失序号。面板会重新读取权威快照并恢复全局事件投影及选区；低于已观察到的缺口序号的快照不能清除缺口。旧版本 PDF 渲染完成后不会替换新版本画面。外部保存时，干净会话复制并验证新基线、自动重载；存在未保存草稿时保留草稿并提示冲突。

## 预览与批注

未安装或尚未启用 Office 能力包时，从文档超链接或文件树打开 Office 文件与 CSV，右侧面板显示“不支持预览，如需预览请升级office功能”。“升级 Office 功能”按钮直接打开组件管理，提供在线安装和 `.artemis-office` 离线导入；启用后自动重新加载文件。旧版 `.doc`、`.ppt`、`.xls` 需要先转换为对应的 OOXML 格式。

## 本地编辑与自动保存

右侧面板保持原有文档布局，单击页面内文字原位修改 DOCX 段落、PPTX 当前页对象文字，以及 XLSX 当前工作表 A1:Z50 内的值和公式。DOCX 文字操作只替换发生变化的部分，原生引擎负责更新预览。Word 页面文字层必须能唯一对应原生目标才提供编辑；表格中的重复数字和文字通过相邻段落上下文区分，短数字的点击范围会扩大并避开相邻文字。上下文仍无法区分位置、旋转文字和跨页段落保持只读，避免误改其他位置。PPT 文字可通过原生对象位置定位；转成路径的艺术字在原位置以普通文字输入，原生引擎保留并重新渲染其效果。该范围不等同于完整 Office 排版编辑器，复杂格式保真门槛仍然生效。

输入停顿约 1–1.5 秒后自动保存，持续输入每 10 秒尝试一次；中文输入法确认后再保存。编辑与保存直接调用本地宿主及已安装的原生引擎，不经过模型或云端转换。保存期间继续输入会排队处理，关闭标签页或正常退出前补存；失败时保留草稿并阻止关闭，界面不会把失败显示为已保存。崩溃恢复依赖本地输入草稿及宿主操作日志。

手动编辑支持 `⌘Z` / `Ctrl+Z` 撤销，`⌘⇧Z` / `Ctrl+Shift+Z` 或 `Ctrl+Y` 重做。撤销历史独立于自动保存，同一次打开期间已保存的修改仍可撤销，退出输入框后也可在文档面板中操作；撤销和重做的结果继续自动保存。连续输入与中文输入法组合按组记录，表格批量粘贴按一次操作记录，公式按公式内容恢复。历史最多保留 100 步并限制文本内存占用，不跨应用重启保留；外部修改发生冲突时拒绝覆盖。批注等其他输入框保留其原生文本撤销行为。

DOCX、PPTX、XLSX 当前自动保存至同目录的 `文件名.artemis-会话ID.扩展名` 工作副本，后续保存更新同一副本，并在顶部状态提示及底部详情显示保存位置；原文件保留。原文件或工作副本被外部修改时拒绝覆盖。CSV 支持单元格编辑、原文编辑，按 UTF-8 写回原文件，保留未展示的行；保存前比对原内容，冲突和非 UTF-8 文件不覆盖。所有新编辑入口及后台保存继续要求 Execute 模式。

新增编辑文案提供中文及英文回退，其他既有 Office 文案保留原有 14 种语言。

## 预览表现

工作台复用右侧标签页，支持 PDF 页码、缩放、跟随修改和区域选取。预览来自内存中的 Office 文档导出，不要求先保存原文件。PDF.js 使用宿主现有 Electron；没有另外加入 Node、Chromium、Python 或 JRE。

批注携带文档、会话、源版本和选区，加入输入框，等待用户发送。区域批注绑定实际画面的版本。当前对象和单元格选取来自快照；Calc 的索引范围是每张工作表 A1:Z50，原生 PDF 使用文档的打印区域。工作表通过 PDF 书签映射到实际打印页码；幻灯片提供当前页附近至多五张缩略图。Office 界面文案覆盖宿主的 14 种语言。Calc 快照使用批量读取；A1:Z50 之外仍不提供单元格索引。

## 构建和验证入口

- `scripts/office/sources.json` 固定 LibreOffice、SDK 与 C++ JSON 头文件来源和 SHA-256。
- `fetch-sources.mjs`、`fetch-corpus.mjs` 下载并验证构建输入和 30 份样本；缓存也重新验证摘要。
- `build-bridge.mjs` 编译自有 C++ UNO 辅助程序；macOS 使用私有构建工具副本修复 SDK 工具加载路径，不修改上游运行时。
- `probe-native.mjs` 验证打开、局部修改、内存渲染、保存副本和重开；其成功不代表格式保真通过。
- `verify-preview.mjs` 使用合成 IPC 与真实 PDF.js/Electron 验证画面变更、过期结果抑制、批注版本和窄窗口布局。
- `.github/workflows/office-native-validation.yml` 提供手动原生验证，并在 `codex/office-workbench` 的相关文件推送后自动运行 Windows x64 验收；不会发布能力包。构建输入缓存每次复用前重新校验摘要，下载中断支持有限次数的续传或重新下载。
- `verify-windows-user.ps1` 仅在临时 GitHub 托管 Windows runner 中创建普通用户，在该用户的应用数据目录通过真实安装服务安装候选 ZIP，使用中文文档路径运行同一批样本。`build-candidate.mjs` 裁剪可选资源及上游 Python；`verify-candidate.ts` 验证离线导入、下载取消、流式升级、回滚、在用版本卸载保护、共享组件卸载后恢复 Lite、修复和实际宿主引擎。候选签名密钥只用于隔离测试，不进入生产目录；流式传输用本机 HTTP 测试端点，不代表公开 HTTPS 发布已验收。
- `verify-windows-client.mjs` 在实际 Windows 客户端的非管理员账户下复验同一候选 ZIP，并清理本次创建的独立安装目录。报告记录实际用户 SID；当前 Windows 11 runner 使用 `NETWORK SERVICE`，其结果属于服务账户验证，不能作为桌面普通用户证据。`prepare-windows-cache.mjs` 为自托管 runner 准备摘要固定的临时 zstd，使候选缓存与托管构建环境一致；不安装机器级工具。
- `.github/workflows/office-candidate-validation.yml` 复用已构建的候选包，在托管普通用户与实际 Windows 客户端并行验收。缓存键、构建提交和归档 SHA-256 显式绑定；验证器可更新诊断，候选 ZIP 保持原字节。完整安装测试记录阶段耗时，上限为 30 分钟，原生样本测试仍单独受 3 分钟上限约束。原生宿主检查保持在修复、卸载、重装之后，启动失败时只在公开样本测试中保留有界诊断。
- 原生引擎连接最多等待 60 秒；首次请求允许连接加操作共 90 秒，收到首个响应后恢复每次操作 30 秒的上限。冷启动超时和桥接进程提前退出均有回归覆盖。
- 验收保留失败报告。Artifact 存储不可用时，`emit-ci-evidence.mjs` 将限定范围的合成预览和公开样本结果压缩到 CI 日志；`collect-ci-evidence.mjs` 校验路径、大小及 SHA-256 后恢复到新目录，不导出引擎用户配置。
- 主程序 Release 流仅运行 `verify-catalog.mjs`，读取已有清单并校验兼容性、签名和已发布资产。它不构建、签名、公证或上传运行时；空目录保留 Lite。

独立运行时的正式签名、公证、发行流程及验收条件见[发布约定](../../projects/office-workbench/README.md#发布前流程)。
