# Artemis 离线授权

## 首次配置（签发者）

1. 在仓库根目录执行 `npm run license-issuer`，或打开已生成的独立注册机应用。
2. 在本机输入至少 12 个字符的口令，点击“创建新私钥”，将加密 PEM 保存到仓库以外的私人目录。分别离线备份私钥文件和口令；遗失口令不能恢复，不能把私钥交给客户。
3. 点击“导出构建公钥配置”，保存为 `apps/desktop/license-public-keys.json`。该 JSON 只含公钥，可以提交仓库；不要在这里放 PEM 私钥。更换密钥时保留旧公钥条目，才能继续接受旧许可证。
4. 重新构建和打包 Artemis。普通开发构建可以在没有公钥时展示锁定页；`ARTEMIS_PACKAGE_BUILD=1` 的正式打包会拒绝空公钥配置。仓库初始配置故意为空，没有万能码、内置签发私钥或生产测试密钥。

运行注册机不会发起联网请求。不要把口令、私钥或用户机器标识写入问题报告。注册机和 Artemis 必须使用同一份公钥配置。

## 日常签发、续期与恢复

用户在 Artemis 激活页复制机器码，你在注册机打开并解锁同一份私钥，粘贴机器码，选择明确的截止日期和时间，生成并复制注册码或导出 `.artemis-license` 文件。界面显示本机时区，载荷记录 UTC 毫秒，截止时刻立即失效。有效期从签发时开始，不能留到首次激活再开始计时。

续期重新签发新注册码。注册码只用于其指定设备；没有自助解绑、离线远程吊销或“旧机器自动失效”的迁移服务。换电脑时签发新码不会撤销旧电脑上仍未到期的码。

时间异常时先校正系统时钟。仍锁定或授权记录损坏时，用户在激活页复制恢复请求，你在注册机展开恢复功能、核对用户与设备后签发恢复凭证。该凭证绑定设备及随机挑战，签发后 24 小时有效，正常存储状态下只能使用一次。恢复只重置时间基准；损坏记录中的原许可证无法恢复时，用户仍需重新输入有效注册码。它不能延长原许可证期限。

激活页提供与主界面一致的 14 种语言，默认匹配系统语言并记住用户选择；页面、授权错误、到期时间和窗口标题同步切换，阿拉伯语使用从右到左布局。

## 客户端行为与边界

- Windows 指纹使用 MachineGuid 与 SMBIOS UUID；macOS 使用 IOPlatformUUID。算法以 `AM1` 标记版本，机器标识不会联网发送。无可靠标识、默认空 UUID、读取失败时禁止授权，不降级为随机标识。Windows 系统重装、主板更换等可能要求重新签发。
- `ART1` 许可证对原始载荷字节使用 Ed25519 签名；主进程验证产品、版本、签名、设备和绝对起止时间。客户端只包含公钥。
- 独立授权窗口拥有仅用于激活的 preload。业务主进程、工作界面与后台服务在授权成功前不会初始化；所有业务 IPC 经过主进程授权适配器，任务创建、Agent 启动、Broker、审批执行及自动化入口也有校验。
- 到期或授权异常会锁住业务调用、隐藏工作界面，先向 Pi 发送取消请求、关闭终端和受管理扩展、等待 MCP 清理，再重启回授权页。退出等待有 5 秒上限。不会回滚已发生的文件修改，也不能终止用户自行脱离管理启动的系统服务。
- 保留聊天、项目、文件和配置。授权失效中断后，自动恢复旧任务及启动时目标续跑受到抑制，用户需要主动恢复；不会重放可能已执行的操作。
- 授权与时间最高值保存在用户数据目录的 `license/state.bin`，使用系统 safeStorage 加密及原子写入。启动、唤醒、每次业务调用都检查授权；运行时每秒检查，另外设置到期定时器，每 30 秒保存时间最高值。
- 五分钟校时容差不会延长有效期；进程内以单调时间约束回拨。存储读取/写入/加密失败时拒绝放行。
- 纯离线不能可靠防御删除全部授权状态后配合改时间、整机快照恢复、克隆/伪造硬件标识或修改程序。系统加密存储不是硬件可信时钟；恢复凭证防重放也不能抵抗完整状态回滚。不宣称绝对不可破解。
- 正式包清除开发服务器和烟测环境入口。签发工具、私钥与测试脚本不进入 Artemis 的构建文件清单。

## 开发与验收

```sh
npm run test:license
npm run typecheck -w @artemis/desktop
npm run typecheck:license-issuer
npm run build
npm run build:license-issuer
npm run verify:license-native
```

`verify:license-native` 在隔离临时目录中生成一次性测试密钥并编译测试应用，不改正式公钥配置，不读取真实用户任务。CI 原生流程使用隔离的临时 AES-GCM 存储夹具，避免依赖 runner 的交互钥匙串；该测试不证明操作系统密钥存储可用性。正式构建始终使用系统 safeStorage，失败时拒绝放行。它分别验证真实 Electron 授权窗口的签名放行/错误拒绝/到期关闭，以及通过授权后启动完整 Artemis 工作界面。测试密钥和临时应用在结束时删除；结果位于 `artifacts/offline-license/`。到期场景使用小型业务窗口夹具，完整业务启动场景使用现有合成烟测数据；这不能代替真实模型执行中到期和第二台物理电脑的验收。

```sh
# 本机注册机调试应用（未签名）
npm run build:license-issuer
node apps/license-issuer/package.mjs --mac --arm64 --dir --config.mac.identity=null

# 分发包；macOS 签名与公证按发布环境单独配置
npm run package:license-issuer:mac
npm run package:license-issuer:win
```

注册机打包在临时独立目录进行，避免收集主仓库的业务依赖；仅包含自身编译文件。正式发布前还需要配置所有者公钥，验证 Windows/macOS 最终包、第二台机器拒绝、签名/公证，以及运行中任务/终端/MCP 的退出。未配置公钥的开发产物不能作为可激活的正式版本分发。

本次环境使用 Node 26 时，既有 jsdom 测试需要 `NODE_OPTIONS=--no-experimental-webstorage`，否则 `window.localStorage` 测试夹具失败；这不是授权逻辑的跳过开关。
