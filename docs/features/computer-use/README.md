# Computer Use

Computer Use 为 Artemis 的 Execute 任务提供 macOS 应用与内置浏览器操作。使用当前支持图片的模型和现有 Pi 循环，不需要另配模型密钥。首版依赖 macOS 14 或更新版本；Windows 不展示该内置插件及 MCP，也不连接迁移配置中遗留的 Computer Use 服务。外部 Chrome 扩展不在本次实现范围内。

## 安装与自动调用

1. 在资源中心的内置插件中安装 **Computer Use**。插件、Skill 和 MCP 服务随 Artemis 分发，不需要用户安装 Swift、Node、Python，也不需要填写 MCP 地址。
2. 安装成功后，Skill 和新增 MCP 服务默认启用。已有服务的手动关闭选择在更新时保留；整体关闭的插件更新不会自动开启新增服务。
3. 在 Execute 中选择支持图片的模型，直接提出任务，例如“在浏览器里填写这个报名表，填好后让我检查”。不需要先提及插件名。
4. 首次访问某个应用时选择“仅本轮允许”“始终允许”或“拒绝”。原生应用还需要 macOS 的辅助功能与屏幕录制权限。授权入口会报告缺失项；授予后重试任务即可。

Execute 的工具列表始终提供轻量的 `computer_open` 入口；调用后加载同一服务的其他工具。Skill 的用途描述帮助模型识别可视界面任务，有直接 API 或文件工具可完成的任务优先使用那些工具。实际选择由当前模型决定，不能保证每条自然语言请求都准确路由。

安装和更新在下一轮刷新当前会话的工具注册表，保留会话历史。正在执行的其他任务继续使用当轮配置。关闭、卸载或撤销授权立即取消相关输入。

“启用”与“就绪”分别表示用户选择和服务连接状态。缺少凭据、尚未完成 OAuth 或连接失败时，插件仍保持安装和启用，资源中心提示设置或重试。这个默认启用规则适用于所有插件新增的 MCP 服务。

## 操作与停止

控制条在 composer 上方随输入区排布，常规高度 40 像素，窄窗口压缩标题并保留停止按钮，不覆盖对话停止按钮。macOS 控制条透出主窗口现有的原生 sidebar 材质，使用与侧边栏相同的明暗色调；其他对话区域保持不透明，降低透明度设置下使用实色。原生浮窗采用相同的 sidebar 材质，去除标题栏，高度 44 像素。停止图标为柔和红色，恢复图标为绿色，按钮文字与背景保持中性。

控制条显示目标应用及前台／后台状态。内置浏览器使用定向 CDP 输入，不移动系统鼠标或激活窗口。macOS 辅助功能允许时在后台读写控件；原生坐标点击、按键和滚动必须先由用户在独立弹窗中允许本轮前台操作。弹窗默认保持后台，拒绝后本轮不重复询问。原生窗口操作期间另有浮动 Stop 按钮。

- 点击停止或手动操作目标界面会暂停控制。同一轮不能通过重新打开目标绕过暂停；用户恢复后或发出新指令后可重新打开。
- 暂停保留具体原因，区分目标应用内键鼠输入、前台输入、停止按钮、原生助手退出和超时；后续工具错误也返回该原因。
- 后台控制期间，在其他应用中的键鼠操作不会暂停任务。用户允许前台控制后，任何真实键鼠输入都会暂停，避免争抢输入。模型不得通过 Shell、AppleScript 或其他工具绕过暂停及前台授权。
- “应用授权”列出持久授权，可立即撤销。任务结束、连接断开、窗口关闭或助手退出都会释放控制。
- 应用授权不替代具体操作的审批。提交、发送、购买、删除等行为应独立调用并经过当前任务的审批规则。
- 页面、窗口和截图内容作为不可信任务数据；插件不提供任意 JavaScript、密码输入或绕过系统授权的接口。

## 工具契约

| 工具 | 用途 |
| --- | --- |
| `computer_open` | 打开本任务的浏览器或指定 macOS bundle ID，授权后返回首个观察 |
| `computer_status` | 查询控制状态与任务归属 |
| `computer_targets` | 列出本任务浏览器及运行中的 macOS 应用，不截图 |
| `computer_observe` | 返回新观察 ID、控件 ID、目标截图 |
| `computer_act` | 执行填充、控件点击、有限按键、滚动或坐标点击 |
| `computer_release` | 释放当前任务的目标 |

动作绑定任务、轮次、目标和观察 ID。最多八步，授权完成后的输入批次预算三秒。已知的连续操作优先合并：多个表单字段一次填写，计算器完整数字／运算符序列一次点击，本地预览按钮可放在填写批次末尾。`fill` 已包含聚焦与替换文本，不需要模型先单独点击。插件内部逐步检查，批次结束时统一返回截图与结果，减少模型往返。

原生控件 ID 绑定实际 AX 对象，内部无标签节点的插入或遍历顺序变化不会重排已有控件 ID。批次中的原生读数变化允许继续，但剩余控件的身份、角色、标签和位置必须保持不变，窗口、几何或弹窗变化仍会停止批次。浏览器导航／结构变化、验证失败或取消也会停止剩余动作。焦点边框等单纯像素变化不会中断后续控件操作。优先使用控件 ID。坐标相对于返回图片，像素改变后必须重新观察；同一批次中执行过其他动作后，坐标点击会要求新观察。

动作结果直接携带新观察，以及 `status`、`attempted`、`completed`、`remaining` 和中断原因。填充未通过值校验不计入完成数；部分完成和阻塞通过 MCP 错误状态展示，保留观察用于恢复。模型直接复用返回的观察，减少多余调用。后台结构检查不生成截图；原生应用首次出现窗口时，助手在三秒内等待 AX 就绪，不需要模型通过 Shell 重开应用。

截图最长边不超过 1280 像素，JPEG 压缩并遵守现有 2 MiB MCP 返回预算。截图未变化时返回 `imageUnchanged` 并复用上一张图片，仍返回新观察 ID。观察耗时、输入耗时和模型推理／网络耗时应分别测量，不能用本地截图速度代表端到端任务速度。

浏览器导航完成并不代表合成器已生成可捕获的画面。`UnknownVizError`、绘制表面暂不可用或空图像会在同一次观察中请求重绘，按 75／150／300 毫秒间隔最多重试三次；成功后读取最新 AX 状态。恢复只重复截图，不重新导航、不激活窗口、不重放输入；停止立即取消，其他错误或持续失败仍如实返回，空图像不会成为有效的坐标观察。

首次打开或导航后还会等待面板尺寸稳定：间隔 100 毫秒检查实际绘制的视口，连续两次一致后返回首个观察，最多等待十次。这样不会把右侧面板展开动画中的中间尺寸交给模型；持续调整窗口仍会如实报错，后续观察和批量操作不增加该等待。目标名称在导航后刷新，避免控制条停留在 `about:blank`。

## 实现边界

主进程管理随机端口、认证令牌和单次调用票据。票据绑定已经批准的精确参数、任务和轮次，模型和 renderer 不持有端点凭据。仅随应用分发且通过安装完整性校验的 Computer Use 可以使用此桥接；复制名称或 MCP 地址的第三方插件不能获得该能力。

生产助手要求 Artemis 与助手具有相同的有效签名团队。未使用团队签名的工程预览包不满足此条件；源码开发使用 `npm run dev` 构建单独的开发助手，开发助手不会进入分发包。

浏览器驱动使用 CDP 的 AX、DOM 和 Input 接口，无模型脚本执行入口。原生助手使用公开 Accessibility 和 ScreenCaptureKit API，通过私有管道连接主进程；生产助手验证父进程标识与签名团队。普通 stdio MCP 的 Seatbelt／AppContainer 隔离保持原样。Plan 和 Review 无 Computer Use 执行权限。

源代码入口：

- `apps/desktop/src/main/computer-use/`：服务、MCP、授权及浏览器／原生驱动。
- `apps/desktop/native/computer-use/main.swift`：macOS 助手。
- `apps/desktop/resources/computer-use/`：安装包与自动选择 Skill。
- `packages/protocol/src/computer-use.ts`：严格动作 schema 和观察契约。

## 开发验证

```sh
npm run typecheck
npm test
npm run verify:computer-use
```

最后一个命令仅在 macOS 运行，创建独立 Electron 配置、真实嵌入式 webview 和临时原生应用。它验证中文批量填表、已有值替换、宿主草稿保留、系统鼠标位置不变、隐藏窗口不激活、点击后读取结果、界面变化停止、任务停止及观察耗时。浏览器保留 GPU 渲染，验证 640 毫秒面板展开动画结束后返回首个观察，额外验证 12 轮导航、隐藏后重新显示及尺寸变化，并记录工具内部恢复的截图错误数量。原生应用延迟创建窗口，验证就绪等待、后台 AX 填写／点击、插入无标签 AX 容器后继续批量操作和前台输入授权边界；纯 Swift 测试验证输入接管范围。截图与 JSON 结果写入系统临时目录。系统权限已经具备时执行原生窗口验证，否则明确记录跳过，不代替用户授权或读取个人应用。

显式设置 `ARTEMIS_VERIFY_CALCULATOR=1 npm run verify:computer-use` 还会操作真实 macOS 计算器，验证清空旧值与 `23 × 17 = 391` 共七步在后台单批完成、控件 ID 稳定性及批次耗时；默认验证不操作计算器。

发布前还须完成真实模型的 20 条 GUI／20 条非 GUI 路由样本、10 类工作流各五次的完成率，以及正式 arm64／x64 安装包的签名、公证、权限归属、更新与回滚验证。当前自动化检查不代表这些外部验收已经完成。目标为观察 p95 ≤1 秒、停止 ≤500 毫秒、控制反馈 ≤100 毫秒；应以目标机器的测量证据判断。
