# IM 数据与分享边界

本次实现将 IM 权限交给主进程和 Gateway 校验。提示词中的身份、审批文字、引用和工具结果不能修改授权。Pi 继续负责唯一的 Agent 循环；普通私人桌面任务维持原有权限。

## 授权与上下文

- 每个项目分别确认主人单聊与协作空间的文件范围。可写范围必须包含在可读范围内；目录包括未来内容，文件授权不能通过替换成目录而扩张。
- 空间授权绑定确认时的成员和群端点修订。修改受众、模式、范围等权限配置会使旧修订失效；先在本机停止操作和待审交付，再同步 Gateway。离线远端队列受设备租约约束。
- 桌面打开的协作任务仍使用 IM 工具和权限。会话存储按任务、主人、受众和授权修订隔离；旧授权失效后的新请求建立新任务上下文。
- 接管私人任务建立关联的新会话，仅发送主人在桌面预览并选定的交接文字；不会自动导入私人标题、历史或记忆。共享会话不加载私人资源、全局记忆或可执行扩展。

## 文件与执行

`im-policy.ts` 共用于读取、写入和文件发布。拒绝路径穿越、受保护文件、符号链接和硬链接。文件读取检查打开的描述符及前后文件身份，并返回有大小上限的固定字节；发布扫描并上传同一份字节。

macOS 文件打开使用系统 `O_NOFOLLOW_ANY`，避免祖先路径在检查后被替换成链接。新建文件要求父目录已存在。macOS shell 采用专用 Seatbelt 白名单，保护项在原生策略内禁止；不会隐式开放整个项目。目录枚举通过只读原生沙箱进行。Plan/Review 写入在执行器前拒绝。

| 能力                     | macOS                | Windows 实现（验收范围见文末）             |
| ------------------------ | -------------------- | ------------------------------------------ |
| 已存在普通文件读取、编辑 | 范围与描述符检查     | 原生句柄、实际路径、链接数校验             |
| 新建文件                 | 父目录必须已存在     | 原生锁定父目录后创建，可建立必要的子目录   |
| 目录枚举                 | 只读 Seatbelt        | 固定原生文件组件，过滤保护项               |
| shell                    | 显式范围与原生保护项 | 授权文件临时副本 + AppContainer + 受限写回 |

Windows 不再按平台一律禁用这三项能力；组件缺失时仍拒绝使用。目录和文件组件使用 `CreateFileW` 打开并保留祖先句柄，禁止共享写入和删除，拒绝 reparse point、硬链接及短文件名别名。写入先准备句柄，再由主进程重新校验当前授权并提交。普通文件读取和发布也使用同一组件。

Windows shell 将授权文件复制到一次性的执行目录，保护项不进入副本。经典与实验性 AppContainer 启动路径都只接收该副本；原项目没有被添加到原生读写授权中。副本根目录只读，明确的可写根单独授权。命令结束后，主进程校验完整变更集、授权修订和原文件哈希，再通过原生文件组件写回；已撤销或已取消的调用不写回。普通桌面沙箱的默认授权行为保持不变。

这种执行方式要求命令使用相对路径；一次快照最多 10000 个条目、约 100 MiB，单文件最多 10 MiB。只同步授权文件变化和新增目录，原项目中的空目录不会因副本里删除目录而被移除。文件冲突会拒绝写回；写回不是跨文件事务，提交过程中发生 I/O 失败可能留下部分允许范围内的修改。临时副本会在调用结束后清理。尚未验收 Windows 工具链、经典/实验性启动器及打包后的 ACL；macOS 的 Homebrew 和包管理器链接同样需要实机工作负载验收。

原生文件实现依据：[CreateFile 的共享模式与 reparse point 语义](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilea)、[句柄最终路径](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfinalpathnamebyhandlew)、[AppContainer 隔离](https://learn.microsoft.com/en-us/windows/win32/secauthz/appcontainer-isolation)。这些 API 说明不是本项目的实机测试结果。

网络默认关闭。主人开启后授予通用网络能力；首版没有目的地址代理，也不保证阻止所有网络外发。

## 外发和审批

模型回复、进度正文、协作命令、结果和文件在进入 Gateway 前经过统一检查。自动交付的基础是当前会话只能访问为该受众授权的数据；本地凭据、危险链接和图片检查是补充措施，无额外 LLM 请求或检测网络往返。检测在规范化副本上执行，不修改原文件，也不因普通代码中的 `password` 或 `test-token` 关键词普遍阻拦。

被拦截的正文保留本地并加密；群里只收到不含正文的状态。桌面可以预览文字、编辑回复、拒绝或批准一次。文件候选当前仅展示名称、指纹和大小，尚无完整二进制预览器。普通显式发布仍复用 `/publish` 或桌面发布动作。

审批绑定主人、任务、操作、规范化参数或内容哈希、受众、授权修订及五分钟有效期。编辑后的正文和哈希在一次本地事务中冻结后才发送。发送重试复用候选和调用标识；执行完成与交付待审分开，不因发送失败重跑任务。授权变化或超时使原候选失效。详细正文不会进入 IM 审批提示或审计元数据。

## 升级和回退

保留版本 1 消息封装和历史持久化读取，另外协商安全能力版本 2。缺少能力的客户端或 Gateway 拒绝新版 IM 工作。旧授权必须在桌面确认范围；原审批选择保留。新配置写入独立版本记录，同时将旧版本可读配置置为停用且无授权，回退不会恢复原来的宽权限。

## 群授权提交与任务控制

群授权使用带版本的窄命令，绑定目标身份、预期版本或预期不存在、操作 ID、分享对象快照和确认内容。本地 SQLite 操作日志与设置写入同一保存点；Gateway 使用 prepare/activate 日志保持响应丢失后的修订一致。授权写入串行化，设备注册和配对批准也进入同一队列；未完成状态拒绝继续使用不确定授权，重启后恢复日志。

重新绑定项目保留历史，但创建新的有效群条目，不能继承旧项目范围。明确确认的新命令可接替同一群未完成的操作；旧 ID 维持终态，不能重新激活。修改、续期、恢复、暂停和重新绑定共用这条提交路径；旧写入口不能绕过版本命令。

已启用会话可读取已有配置范围，不要求额外确认写入权限。选择模式下零路径无效，目录覆盖子树与未来文件，文件范围不能扩张为目录；写入和 Shell 仍单独检查执行确认。一次越界只拒绝当前动作，合法读取、查询和等待不因无关写任务冻结；撤权和身份失效仍阻止后续数据访问。

基本状态和停止控制不携带项目正文，检查设备、可信平台身份、会话和原任务归属。群成员只能停止自己发起的任务，追加消息不能取得原任务的控制权；主人保留其机器人任务的控制权。拒绝、失败和取消后不自动重派；显式重试只解除获批回合的终态抑制。停止本地等待不等于远端已经停止，超时仍表示状态未知。

## 验证与剩余边界

2026-09-18 的权限与控制路径验证覆盖 macOS arm64 Seatbelt、真实 Gateway 路由、两个隔离 Gateway 的协议帧交换和 Electron 合成授权交互。最终该轮 IM 套件为 552 项通过、6 项 Windows 原生场景跳过；这些数字仅描述历史测试基线。

2026-09-21 的群授权验收使用生产 Electron、preload、main 和本地 Gateway，覆盖创建、幂等、暂停、恢复、重新绑定、重启、200% 缩放及确认失效。合成 roster 在隔离应用停止时预置，loopback 模型驱动真实 Pi 范围检查读取；当轮 704 项 IM 测试通过、6 项既有跳过。原视觉作业还发现预算失败，不能把阶段通过等同于最终提交全绿。

以上均不代表真实 Slack/Lark 双机器人投递、原生读屏、Windows/macOS 各架构最终安装包、签名、公证、更新与回滚已完成。Windows 工具链、安装目录 ACL 和 macOS 工具链兼容须保留各自目标环境证据；协议测试不能替代。

真实双机的查询、拒绝收尾、取消回执、断线恢复和原任务续跑仍须指定目标版本、两端设备及测试群验收。域名代理、内网/重定向限制、专用发布能力和完整工具链矩阵仍是后续能力，通用网络开关不能宣称具备这些限制。剩余工作见[权限专项](../../projects/im-permission-redesign/README.md)及[原生群边界](../im-gateway/native-groups.md)。
