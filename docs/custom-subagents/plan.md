### 三、数据契约与迁移

建议新增 `custom_agents` 与 `custom_agent_projects`，不拆出第二套配置服务。

定义最小字段：

```text
id, revision, name, description, color, enabled
instructions
scope: all | selected
modelPolicy: inherit | fixed(providerId, modelId)
thinkingPolicy: inherit | fixed(level)
toolPolicy: inherit | allowlist(toolRefs[])
allowAutomaticInvocation
triggers[]
createdAt, updatedAt
```

- `id` 永久标识定义，`revision` 每次修改递增；名称用于展示与检索，不用于关联。一期名称规范化后唯一，触发词允许跨定义重复并按歧义处理；不额外增加别名字段。
- 关联表明确为 `(agent_id, project_id)`，复合主键，分别引用定义与项目。`scope=selected` 且零关联表示无适用项目，永远不能自动变成 all。
- 新建时默认当前项目、允许手动调用、关闭自动调用、继承模型及工具；没有项目上下文时要求用户选择范围。编辑提示继承的是现有子智能体能力上限。
- 定义正文和关联在同一事务保存；更新携带 `expectedRevision`，冲突返回 `REVISION_CONFLICT`，保留表单内容供刷新处理，不能覆盖另一窗口的更新。
- 主进程校验字段大小、枚举、项目存在性、模型引用结构和工具引用结构；具体长度上限在 PR1 固定并测试。颜色使用受控 token，不接受任意样式。
- 删除定义级联清理关联；执行历史继续保留 ID、版本、名称快照，不通过外键级联删除历史。删除项目只清理关联，隐藏项目不等于删除项目。
- 关联以可信的 `projectId` 判断。Local 与 managed worktree 共用项目身份，迁移路径不影响关联。无项目任务仅可使用 all 定义；不能由模型传入任意 projectId 扩大范围。
- 迁移为增量且事务化，旧库初始为空目录。迁移失败须回滚并明确报错，不能静默开启不完整功能。覆盖新库、旧库、重复启动、迁移中断与外键行为。

凭据仍留在原有加密配置体系；定义只引用 provider/model ID。SQLite 中的专用指令本身可能敏感，设置编辑接口可读正文，普通候选目录、日志、诊断包不得携带正文。

### 四、工具、权限与指令契约

有效能力按以下交集计算：

```text
当前 RunMode 允许的能力
∩ 既有子智能体运行时基线
∩ 父级允许向下传递的能力
∩ 定义工具策略
∩ 派发时冻结的能力上限
∩ 执行时仍有效的连接与信任授权
```

1. `inherit` 与 `allowlist: []` 严格区分；空白名单表示没有业务工具。失效工具不得触发“继承全部”回退。
2. 内置工具使用稳定工具 ID；MCP 使用 `serverId + toolName`，在宿主映射到运行时名称，不能用 label 或动态名称匹配权限。
3. 保持现有子会话只读标记 MCP 与无可执行扩展的基线。MCP 的只读标记不是任意服务器绝无副作用的证明，不借此扩大信任。
4. Plan/Review 无 shell、MCP、可执行扩展；文件、office、附件、远程操作等业务入口都按实际操作校验模式与权限。工具列表过滤和执行前检查同时存在。
5. 完成、取消、等待与必要团队状态控制由宿主管理；`spawn_agent` 不是不可撤销的控制能力，自定义实例必须从工具集和执行入口同时禁止再次派发。
6. `write_paths` 继续约束既有协作写入接口，不把它宣传为 shell 目录沙箱。允许 shell 时准确展示当前桌面用户权限；“只读”配置必须排除 shell 及全部有副作用能力。
7. 专用指令追加在受控指令位置，保留 Artemis 身份、模式约束与团队协议；不能覆盖基础系统约束，也不能通过提示词授予权限。
8. 连接撤销、项目范围收窄、定义停用/删除通过主进程到 worker 的有序更新处理；启动前重查。无法确认授权状态时不能启动，运行中下一次工具调用不得使用已撤销能力。

有效工具预览与运行时复用同一计算逻辑。设置页标注“项目/模式预览”；尚未确定父会话时，不把预览称为最终权限，实例页展示实际解析结果。

#### 派发接受与预算扣减的具体边界

当前 `runtime.ts` 的 `createSpawnAgentTool` 在第 3993 行检查 spawn 预算；`launchChildAgent` 从第 4517 行开始，第 4522 行即生成实例 ID，第 4547 行再次检查预算，第 4579 行加入成员列表，第 **4581 行执行 `team.spawnCount += 1`**，第 4584 行登记 `hosted.childAgents`，随后发事件并等待依赖。重试同样调用 `launchChildAgent`。上述行号对应本次增补提交，实施时以符号与语句重新定位。

PR1 固定、PR3 落实以下顺序：调用去重检查 → 引用/P1 校验 → 范围、模式、模型与工具解析 → 当前团队预算复查 → 不可分割的接受步骤（分配实例、登记成员、扣减一次预算）→ 排队。所有可能异步等待的校验之后，必须在接受步骤再次检查预算及授权版本；同一调用的并发副本共用一次接受结果。拒绝路径不能调用现有会先分配 ID 的 launch 函数，再靠回滚假装“没有接受”。

回归必须比较拒绝前后的 `spawnCount`、成员列表、childAgents、并发队列及子实例事件：P1 拒绝不改变以上状态；允许独立的路由拒绝审计。纠正后第一次成功调用仅增加一个成员、扣减一次；重复投递不再扣减。已接受后因停用/取消而释放并发资源，不返还单轮累计 spawn 预算；用户明确重试创建新 attempt，按现有预算计费。

### 五、冻结、失效与重试

每轮建立目录快照，包含定义 ID、revision、名称、描述、调用策略等必要路由元数据。自动目录仅含允许自动调用的定义；手动候选包含启用且符合范围的定义。

在**接受派发、进入依赖等待/并发队列之前**冻结：定义内容、解析后的模型/思考强度、能力上限、projectId、目录标识与路由依据。继承模型取当时父实例实际选择；固定模型不受后续父模型切换影响。上下文窗口等派生配置按解析后的子模型能力计算，不能盲目照搬父模型参数。

| 后续变化                                 | 行为                                                                                      |
| ---------------------------------------- | ----------------------------------------------------------------------------------------- |
| 普通编辑、改名、增加工具权限、父模型切换 | 已接受实例沿用原快照，后续轮次使用新目录；不因权限增加而扩权                              |
| 定义停用、删除、移出当前项目             | 阻止新派发；取消尚未启动实例，释放等待/租约；运行实例不热换指令，用户可用现有取消入口停止 |
| 撤销工具授权、断开 MCP                   | 执行时拒绝相关工具，不通过旧快照维持权限                                                  |
| 固定模型或凭据不可用、思考档位不兼容     | 明确失败，不静默换模型、供应商或档位                                                      |
| 用户重试                                 | 复用原快照，重新检查当前模式、范围、启用状态与授权；不能因重试扩大原能力                  |
| 应用重启                                 | 还原历史展示，按现有机制标记中断；重新执行是新实例，不假装恢复原 Pi 会话                  |

原始配置快照只用于进程内执行与重试。本期持久化最小审计元数据及摘要，不持久化可恢复的完整秘密配置，也不承诺跨重启按旧指令重跑。

### 六、结构化 @：完成确定性的手动调用

选择候选后，草稿保存类似 `{kind: custom-agent, definitionId, revision}` 的结构化引用和展示文本；纯文本 `@名字` 本身不获得调用授权。候选与 skill/文件等类型分组，删除 token 同步删除引用。

发送链路：

```text
输入框引用 + 本轮任务
→ 主进程重新校验 ID、版本、范围与启用状态
→ 宿主接受一次显式调用，分配调用幂等标识
→ 共用 spawn 的预算/权限/快照/队列入口
→ 一个 Pi 子实例执行
→ 结果进入原团队/主会话，由主智能体汇总
```

关键点是宿主落实调用，不能只在 prompt 写“请调用”。不另建 agent loop，也不允许模型伪造“用户显式”来源绕过自动调用开关。

- 一期一次发送最多一个自定义定义；正文作为任务，附件沿现有受控交接路径传递，不复制主对话全部历史。
- 用 turn/显式调用 ID 绑定唯一实例，重复投递、恢复和主模型重复请求不得产生第二个相同显式实例。
- 改名仍以 ID 识别；发送时 revision 过期则要求刷新选择，保留草稿。删除、停用、越范围明确报错，不改成自由角色。
- 仅关闭自动调用不影响合法手动调用；手动调用仍不能越过模式、权限、并发和团队预算。
- 用户主消息在发送队列等待时，出队再次校验引用；子任务一经接受才按上一节冻结。这两类队列分别测试。

#### 现有去重能力与必须新增的调用记录

已核对的链路是 renderer/preload → `startTaskTurnUnchecked` 或 `queueTurn` → checkpoint/`dispatchCheckpoint` → worker → runtime；恢复另经 `prepareRecoverableQueuePayload`、`RecoverableTurnQueues.recover` 与 `resumeInterruptedTurns`。

- `startTaskTurnUnchecked` 当前每次生成新 turnId；`dispatchCheckpoint` 每次生成新 dispatchId/requestId。它们是轮次或请求标识，不能直接充当用户重复提交的稳定幂等键。
- `RecoverableTurnQueues` 是内存 Map：add 使用进程内递增 ID，reconcile/recover 按 runtimeText 匹配，公开恢复项仅保留文本/附件。它支持队列关联和恢复，但没有自定义定义引用或跨重启调用唯一性。
- 协议 reducer 用 eventId 去重，保护的是事件投影；不能阻止一个重复命令在事件发出之前再次创建 Pi 子实例。

因此以下是**新增工作**，不能按“已有幂等原语”估算：

1. 为本次显式提交生成稳定 `invocationId`，网络/IPC 重试沿用，用户新发一条同文消息生成新 ID。可信主进程绑定 threadId、定义 ID/revision 与请求内容指纹，同一 ID 对应不同内容返回 `INVOCATION_CONFLICT`。模型不能提供或冒充用户来源。
2. 将 ID 与结构化引用贯穿发送输入、普通/压缩期间 follow-up 队列、checkpoint、worker 命令及恢复项；队列重排保留身份。编辑尚未提交执行的队列项须失效旧调用身份并生成新 ID；纯文本恢复不能猜出丢失的结构化引用。携带 @ 的消息一期作为新轮次/follow-up 执行，不通过 steering 偷渡直接派发。
3. SQLite 新增最小 `custom_agent_invocations` 记录（threadId、invocationId、请求指纹、definitionId/revision、绑定 turnId/instanceId、状态与时间），唯一键为 `(threadId, invocationId)`，不以 turnId 为唯一键的一部分，防止恢复生成新轮次后再次接受。状态至少区分待处理、已承诺派发、已结束、已取消、结果不确定；不存专用指令全文。随所属任务清理，不提前删除会被恢复路径引用的去重记录。
4. 主进程持久化唯一记录并串行协调同键请求；worker 内也在创建实例前按该键复用正在接受的 promise 或已登记结果。持久化派发承诺必须在可能启动子实例之前完成，关联固定 instanceId；该协议需显式覆盖“写库成功但命令未送达”和“子实例已启动但回执丢失”两个故障窗口。
5. 同进程重复请求返回同一实例/状态。若进程崩溃后无法确定已承诺派发是否启动，标记结果不确定/中断，**不自动再次派发**；用户选择重新执行才生成新 invocationId，并记录替代关系。明确保证正常流程唯一接受及恢复时不盲目重跑，不宣称数据库与 Pi 会话之间已具备跨进程 exactly-once 执行事务。
6. 主模型在当前轮再次要求执行已绑定的同一显式调用时，返回既有实例；不靠全文相同推断任意两个任务等价。同一定义的其他独立任务仍可正常创建。

PR1 定义状态机、事务/IPC 顺序与故障窗口测试，PR2 建表，PR3 实现接受端，PR4 接通 UI/所有队列。测试至少包括：并发重复发送、回执丢失、恢复重放、相同 ID 不同内容、相同文本不同 ID、队列编辑/重排/压缩、派发承诺前后崩溃；分别断言实例数、预算与用户可见状态。

### 七、P0–P3 优先匹配的最终语义

采用补充中的分层思想，但必须区分“文字匹配确定”与“角色适合任务确定”。例如出现 `PR` 不能证明应由审查员处理，也可能是在写文档或引用讨论。

| 层级              | 条件与处理                                                                                              |
| ----------------- | ------------------------------------------------------------------------------------------------------- |
| P0 用户显式引用   | 经可信发送链路验证的定义 ID 必须命中；无效则失败，不走自动回退                                          |
| P0 显式工具参数   | 模型传入定义 ID 时验证该调用者的调用权限；有效则直接使用。审计注明来源是模型，不冒充用户选择            |
| P1 确定性词法匹配 | 对规范化后的 role 精确名称，以及 task 中明确边界的名称/触发短语建立候选；这是候选规则，不能宣称语义正确 |
| P2 语义选择       | 主模型根据名称/描述目录选择 ID；没有额外模型服务、embedding 或隐式网络调用                              |
| P3 自由角色回退   | 无明确匹配时保留现有行为并记录原因；目录为空时与旧行为一致                                              |

P1 的校验与纠偏（PR5 不得进一步退化成纯提示词约定）：

- role 精确命中唯一有效定义而省略 ID：返回 `CUSTOM_AGENT_REFERENCE_REQUIRED` 及候选 ID，要求用明确引用重试；拒绝发生在分配实例和扣减 spawn 预算之前。
- 只因任务正文命中触发词：给出候选建议，不直接强制改派。多个候选则返回歧义候选，不按最近使用或项目顺序擅自选定“正确角色”。
- 规范化规则固定并测试：Unicode 规范化、大小写处理、拉丁词边界、中文短语边界策略；不允许 `PR` 子串命中其他单词，不支持用户正则表达式。
- 不让模型无限重复同一错误：同一委派意图的一次纠偏后，重复无效请求仍拒绝且不创建实例，由主智能体说明无法派发；不以“达到重试上限”为由自动绕过硬校验。
- 模型显式选择了合法定义后不再被另一触发词覆盖；关闭自动调用的定义不参与自动匹配。

目录采用“当前项目 selected 定义优先，再按稳定名称/ID 排序”。最近使用排序与累计 N 次回退后建议建角色暂缓，避免增加状态和路由漂移。设置显式目录数量与文本总预算，达到上限时提示并要求收窄自动启用范围，不能静默截断生效集合；具体预算在 PR1 固定、PR5 以评估验证。

PR5 的三个独立发布阻断测试必须走真实工具执行入口并检查状态，不能仅断言工具描述文案：① role 精确命中唯一自动可用定义且缺 ID，返回 `CUSTOM_AGENT_REFERENCE_REQUIRED`、零实例/零预算增量，补 ID 后成功；② task 触发词误报仅给建议，不因该词拒绝合法自由角色，也不自动换角色；③ 多候选歧义返回/展示候选而不擅自定一个，合法显式 ID 能消除歧义，只有触发词歧义时仍允许有理由的自由角色回退。关闭自动调用、空目录及用户 P0 压过其他触发词分别作为对照。三个测试任一失败均不得开启自动路由。

审计将 invocationSource 与 selectionBasis 分开记录，避免把模型主动填 ID 的语义选择错误统计成确定性用户调用。

### 八、事件与界面闭环

路由审计至少包含：schemaVersion、eventId、turnId、parentAgentId、instanceId（接受后）、projectId、目录 ID/候选 ID 与 revision、选择的定义 ID/revision、调用来源、匹配依据、结果/错误码、实际模型及能力摘要。目录快照每轮存一次，实例引用它，避免重复膨胀。

现有版本化 envelope 与幂等 reducer 处理事件；重放不能重复添加实例或统计用量。默认不保存任务全文、提示词全文、凭据或完整工具输入；不根据原始任务文本建立隐式用户画像。

设置 → 智能体新增子智能体区块，保留原内容与布局。表单包括名称、描述、颜色、专用指令、模型/思考策略、工具策略、项目范围、自动调用开关及可选触发词。支持启停、删除与明确的校验错误；停用/删除时说明排队及运行实例的处理结果。

实例页显示定义名称、版本、实例标识、实际模型、路由来源及失效原因；保留 role、label 的团队语义，不用定义名称覆盖全部职责信息。同一定义多实例以实例 ID 区分，版本放次级信息。

使用现有组件与主题 token，覆盖中英文、浅色/深色、长名称、窄窗口、键盘操作、焦点返回及中文输入法。同步相关 `docs/ui-prototype` 页面与验收清单，不把静态原型当作生产交互验证。

### 十、必须覆盖的验收矩阵

| 领域     | 关键场景及断言                                                                                                                       |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 范围     | 删除最后一个项目不变全局；Local/worktree 同归属；路径迁移不丢关联；无项目不能使用 selected                                           |
| 权限     | Execute/Plan/Review × inherit/空白名单/指定白名单；父级限制、失效 MCP、远程工具入口、自定义嵌套调用均不能扩权                        |
| 只读     | 指令要求写入、shell 绕写、通过 office/附件/远程入口写入均按能力拒绝；宿主取消与收尾仍可用                                            |
| 快照     | 等依赖与等槽位时编辑定义、切换模型；启动仍使用原快照；固定模型不可用明确失败                                                         |
| 撤销     | 队列等待中停用/删除/移出项目；不得启动且释放资源；运行中撤销工具后下一调用拒绝                                                       |
| 重试     | 原版本和能力上限复用；当前模式更严格时只收窄；停用/删除后不能重试绕过                                                                |
| @        | 重命名、过期版本、删除、多个选择、IME、草稿恢复、重复投递；合法选择恰好一个实例                                                      |
| 路由     | 用户 P0 压过触发词；模型不可伪造用户来源；P1 唯一名称硬纠偏、触发词误报、多候选歧义分别走执行入口并作为 PR5 发布阻断测试；空目录兼容 |
| 调用幂等 | 并发副本与回执丢失只接受一次；同 ID 异内容拒绝，同文异 ID 可执行；队列编辑/重排/压缩及崩溃恢复不盲目重跑；验证记录、实例数与预算     |
| 持久化   | 旧事件读取、重复事件、乱序/恢复路径、同定义多实例；诊断不导出专用指令                                                                |
| 团队     | 依赖、并发租约、取消、深度/数量/单轮预算保留；被拒绝请求不消耗实例预算                                                               |
| UI       | 中英文与双主题，焦点/键盘、长内容、空状态、失效模型/工具、保存冲突及有效能力预览                                                     |

先运行针对性策略与 store/runtime/UI 测试，再执行 `npm test`、`npm run typecheck`、`npm run build` 以及仓库要求的原型/UI 检查。以隔离用户数据和合成项目执行真实 Electron 流程，避免使用个人提示词作为截图素材。

自动委派评估使用固定合成任务集，覆盖应当不委派、应选某定义、多定义歧义和无匹配；报告正确选用率、误选/漏选率、重复工作、任务成功率、耗时、token 与成本。确定性及安全断言要求全部通过；概率性指标先记录关闭自动路由时的基线，再在固定模型/配置下比较，不承诺 100% 语义匹配。

Windows/macOS 的结果分别记录。协议测试或单台 macOS 的通过不能声称跨平台验收；发布时按项目合同提供对应真实平台、最终打包产物及签名/更新等发布证据，不在本计划中预先宣称完成。

### 十一、回退与完成标准

采用增量数据库结构，不在回退时删除定义数据。自动委派可独立关闭；定义执行能力出现问题时停止接受新的自定义调用并清楚说明，不能把显式请求静默变成自由角色。已运行实例由既有取消/收尾路径处理。

旧版本对新增数据库与事件的兼容性必须实测；如果不能安全降级，使用升级前备份和明确恢复步骤，不能直接让旧二进制读取未经验证的新库。

完成标准：用户能够创建专业子智能体，将其绑定指定项目，在 Local 与 managed worktree 中通过 @ 唯一调用，看到实际模型/版本/结果；编辑、排队、停用、删除和重试均符合快照契约；自动路由可解释、可关闭；现有自由角色与安全边界无回归。最终交付附实现提交、测试结果、真实 UI 证据和仍未验证的平台范围。队友提出的三项补点已分别纳入第四节预算边界、第六节调用记录与恢复协议、第七节 P1 发布阻断测试，并同步进入 PR1–PR5 出口；它们是必须兑现的交付项，不是已通过的验证结果。
