按 [专项方案](../../proposal-im-settings-redesign.md) 实现，仅供交互评审。页面使用虚构设备、账号和连接数据；启动服务、注册、连接、配对和保存均为内存中的演示状态，刷新即重置。复制按钮会实际写入剪贴板。请使用演示值体验表单。

## 已实现的交互

- 六步垂直向导，当前步骤高亮，平台约束在填写凭据前可见。内置服务演示自动注册，保存机器人凭据后自动生成配对码，配对成功后自动进入管理态。
- 管理态包含三个渠道和四个通用入口。头部集中显示状态与唯一连接开关；缺少设备或连接时禁用并说明原因，暂停保留配置。
- 凭据按“已保存 → 更换 → 保存 / 取消”展开，密钥不回填；管理凭据成功使用后清空。配对请求批准或拒绝后移除，账号解绑采用行内确认，支持 Escape 取消及焦点归还。
- 配对码五分钟倒计时，过期禁止复制和模拟配对，可重新生成。项目授权支持选择、默认项目、模式及权限依赖、到期时间和续期。
- 群协作按方案保留默认折叠的高级区：成员 / 群聊诊断、演示配置填入、JSON 校验，以及保存后的各群确认指令。
- 渠道导航支持方向键循环、Home / End；紧凑态将通用入口收入菜单，支持键盘选择、Escape 和点击外部关闭。

## 与用户提供基线的差异

用户提供的是 v17：对话框为 `860 × 560`，原有五个标签且尚无消息接入。方案示例使用较新的 `920 × 760` 骨架及不同标签文案。本次保留 v17 的尺寸、原有标签文案、顺序、图标和内容，只在“更新与诊断”前插入消息接入入口，并为原有内容增加隐藏容器。

原有内联 CSS / JavaScript、组件目录页与 T8 断言均保持原样，由基线指纹校验。新增样式限于消息接入内容区，沿用现有字体、状态色、圆角与表单样式；管理态内栏宽 150px，详情独立滚动，凭据与高级内容按需展开。

方案第 3 节使用“对话框可用宽度不足约 720px”，第 6 节又写为“IM 内容区宽度小于 720px”。在本次较小基线下，后一种解释会始终触发紧凑态。因此采用**对话框宽度小于 720px**作为断点。外层在视口小于 980px 时转为横向标签的旧规则保持不变；390px 窄屏时这些标签仍会占用较多高度。

平台字段以当前 main 的实际表单为准：企业微信 5 项、飞书 8 项、Slack 2 项及 2 项可选高级字段，团队模式另需 Gateway 管理凭据。方案映射表中的企微 / Slack 数量存在口径差异。本次未添加额外必填项。

## 验收与复跑

依赖本机 Chrome、Node.js，以及可导入的 Playwright。静态页面本身不需要安装依赖。保持预览服务运行后执行：

```sh
node docs/ui-prototype/tools/verify-im-settings.mjs /tmp/artemis-im-settings-qa
```

若 Playwright 未安装到当前项目，可通过 `PLAYWRIGHT_MODULE` 指向已有安装的 `playwright/index.mjs`；服务端口不同可设置 `IM_PROTOTYPE_URL`。脚本使用隔离的无头 Chrome，保留浏览器沙箱，不接入用户浏览器资料。

2026-09-05 实测：Chrome `152.0.7977.76`，16 / 16 组检查通过。

| 检查 | 结果与证据 |
