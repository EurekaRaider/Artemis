# 专项方案 ·「消息接入」设置面板排版重构(静态原型先行)

> 依据 [discussion #76「提案:建立 Artemis 自有 UI 设计语言」] 体系。
> 背景:main 仓库 `6b9ee56`(v1.4.61)合入 IM 网关协作(企业微信 / 飞书 / Slack + Gateway / 设备注册 / 配对 / 项目授权 / 群协作空间),其设置面板为单栏六步长页;feat/im-feishu 分支已有主从双栏面板(`SettingsPanel.tsx` `im-section`,含 `im-layout / im-channel-list / im-detail / im-block` 四层 CSS 骨架)。本方案将 feishu 版双栏思路扩展为三态面板,覆盖 main 版全部设置项。
> 本文仅为静态原型阶段的排版规格,不改动任何产品源码。正式 React/Electron 迁移按 `capability-matrix.md` 口径另行立项。

## 1. 范围与非目标

**范围:仅「消息接入」tab 的内容区**(`apple-inspired-ui.html` `#settingsPanelIm` 及其 `workspace.css` / `workspace.js` / `fixtures.js` 配套)。

**非目标(零改动项):**

- 设置对话框骨架:`.settings-panel` 尺寸体系(max-width 920px、`min(760px, …)` 高度)不动
- 左侧竖排 tab 栏:`Tabs orientation="vertical"`(常规 / 模型 / Agent / 能力 / 消息接入 / 维护)结构、顺序、图标不动
- 其他 5 个 tab 的内容不动
- 现有 T8(70 卡契约)/ T9(页面布局门禁)断言不回归

## 2. 现状诊断

| 维度 | feishu 分支参考版 | main 仓库现状(v1.4.61) |
|---|---|---|
| 布局 | 主从双栏:左侧渠道卡片,右侧详情 | 单栏纵向长页,六个步骤区块顺排 |
| 状态呈现 | 头部状态胶囊 + 每渠道状态点 | 分散在第 1/2/3/4/5 步各处 |
| 核心开关 | 无此概念 | 「启用 IM 连接」Switch 埋在第 5 步约 75% 屏深 |
| 平台切换 | 左栏点渠道卡片 | Select 下拉,下方表单联动重渲 |
| 平台指引 | 折叠式 + 权限 scope 芯片 | 一大段 `<ol>` 长文常驻 |
| 凭据呈现 | 已保存 → 提示 +「更换」按钮 | 凭据表单常驻 |
| 向导/管理 | 无向导 | 六步向导与管理混在同一条滚动流 |

核心问题:**首次设置(向导)与日常运维(管理)混在一条滚动流里**。配置完成后,用户最高频操作(看状态、开关连接、解除绑定)都要在长页面里翻找。

另注:原型 `#settingsPanelIm` 当前镜像的是 feishu 分支旧面板(飞书在用,钉钉 / 企微「即将支持」);本方案对齐 main 仓库三平台口径(企业微信 / 飞书 / Slack 均可配置),钉钉不再出现。

## 3. 目标信息架构:三态面板

```
向导态(零配置)──任一渠道已连接且配对成功──▶ 管理态(日常运维)
                                              │
                     对话框可用宽度不足 ~720px ─┴─▶ 紧凑态(渠道栏折叠为横向条)
```

- **向导态**:右侧呈现六步垂直进度清单(复用 main 版 `ImSetupGuide` 的步骤与完成判定),当前步高亮,点击跳到对应详情块;底部并排三张平台差异卡(企业微信·长连接免公网 / 飞书·需 HTTPS 回调 / Slack·Manifest 导入),让用户在填表前看到平台约束。
- **管理态**:左侧导航栏 + 右侧分块详情。左栏两组:「渠道」(企业微信 / 飞书 / Slack,各带状态点)+「通用」(Gateway 与设备 / 配对与账号 / 项目授权 / 群协作空间·高级)。
- **紧凑态**:内层左栏降级为顶部横向分段条,「通用」入口收进尾部 `▾` 菜单;详情区占满剩余宽度。

## 6. 布局与令牌规格

### 尺寸预算(按 920px 对话框)

```
.settings-panel(max-width 920px)
└─ tab 栏(竖排,现状不动)                        ~170px
   └─ #settingsPanelIm(IM 内容区)                 ~700px
      ├─ .im-layout(grid,管理态)
      │  ├─ .im-channel-list(内层左栏)            150px 固定
      │  └─ .im-detail(详情区)                    ~530px 自适应
      └─ 头部行(标题 + 状态胶囊 + 主开关)          全宽,双栏之上
```

- `530px` 详情区可容纳单列 `TextField` / `Select` 与状态行,无需加宽对话框
- 紧凑态断点:IM 内容区可用宽度 `< 720px` 时 `im-layout` 切换单列,渠道栏变横向分段条(与皮肤矩阵 compact / 200% 顶点对齐)

### CSS 骨架(沿用 feishu 分支已验证四层类名)

```
.im-layout            管理态双栏容器(grid 150px + 1fr;紧凑态 1fr)
.im-channel-list      内层左栏(渠道组 + 通用组两组卡片)
.im-channel-card      渠道卡(可选 / 选中两态 + .im-dot 状态点)
.im-detail            右侧详情(详情头 + 条件卡 + 块序列)
.im-block             详情内分块(h4 小标 + 内容,替代 ManagementSection 满宽堆叠)
.im-identifier        等宽 chip(ID / 回调地址 / 配对码 / JSON)
```

### 令牌纪律

- 状态点三态沿用皮肤 token:ok(连接)/ bad(错误)/ pending(连接中、待确认),不引入新色
- 主开关、危险操作(确认解除)各仅一处,避免双重指示
- 倒计时、到期时间、重试计数启用 `font-variant-numeric: tabular-nums`
- 折叠块统一 `▸/▾` 文字符号,禁用 emoji 图形

## 7. 交互与状态规格

1. **向导态 ↔ 管理态切换**:任一渠道 `connected` 且存在已配对 identity → 管理态;手动入口:管理态详情区顶部「重看设置指引」可回放向导(只读跳转,不清配置)。
2. **配对请求卡**:仅当存在 `pairingAwaiting` 时渲染于当前渠道详情顶部;批准 / 拒绝后即时移除并刷新绑定列表。
3. **凭据已保存态**:显示「已保存 · 更换」;点「更换」原位展开表单,取消恢复已保存态;保存成功回到已保存态。密钥类字段回显时一律不回填明文。
4. **解绑内联确认**:行内展开「确认解除 / 保留」,焦点移入确认按钮,Esc 视为保留;不使用弹窗。
5. **左栏键盘可达**:渠道卡与通用组条目为 `tablist` 语义(对齐现有 `settings-tab` 键盘模型),方向键循环,选中即切换详情。
6. **主开关守卫**:无设备编号或无已连接渠道时禁用并附一行原因;关闭开关不清除任何配置。
