# IM 权限与真实群协作验收

核心权限改造、默认读取与执行确认分离、查询/取消控制及拒绝终态修复已进入主分支。当前专项保留尚未完成的真实双机和目标平台验收；长期行为约定见 [IM 安全边界](../../features/im-security/README.md)，使用与平台限制见 [IM 功能文档](../../features/im-gateway/README.md)。

## 已实现范围

- 目录导航返回授权根的投影视图。一次越界只拒绝当前动作；读取、状态与等待不因无关写任务占用而被冻结，撤权与身份失效仍拒绝后续数据访问。
- 写入和命令按项目执行期排队，可取消，并在真正执行前复查授权。文件写入支持内容哈希或“必须不存在”的前置条件。
- 确认和操作版本按分享对象保存。缩小范围建立干净上下文；群名修改不轮换权限版本，增加其他受众不会自动授予当前群权限。
- 整个项目写入是显式能力，包含未来普通文件；旧的“全选条目”不自动升级。macOS 命令使用独立 HOME、缓存和空 npm 配置，未知运行时不会得到更宽目录权限。
- 默认读取只使用已启用会话的配置范围；写入及 Shell 继续要求执行确认。状态、停止和取消按可信身份及原任务归属处理，不能因文件授权失效而失去基本停止能力。
- 拒绝、失败、取消后不会自动重派；拒绝回执刷新等待及最终结果，不能用较早的模型文本表示仍在等待。显式重试仅解除该次获批回合的终态抑制。
- 后续群授权管理使用带版本的窄命令、持久日志和 prepare/activate 恢复；细节与生产夹具证据已合并到安全边界文档。

## 已有证据及其范围

2026-09-18 的实现与控制路径复查对应 `1c6b36d`、`85e3e702` 等提交。本轮最终 IM 套件 41 个文件、552 项通过，6 项 Windows 原生场景因平台不同跳过；类型检查、生产构建与 diff 检查通过。

macOS arm64 原生 Seatbelt 检查覆盖普通新目录、隐藏缓存及 Node/npm；项目外秘密、凭据、控制配置和链接逃逸仍被拒绝。Electron 授权界面使用隔离配置和合成状态，Gateway 集成使用两个隔离实例。历史截图与报告位于 `artifacts/im-permission-redesign/`；未随文档提交的本地产物不能当作长期附件。

现场诊断曾确认一个真实拒绝回执与陈旧等待文案之间的差异，但没有读取对端数据库，不能据此断言对端授权状态失效的原因。该诊断也不代替完整双机验收。

## 待验收

1. 两台设备安装同一目标版本，在指定 Slack/Lark 测试群完成真人发起、A 委派 B、B 接受并执行、结果回传、A 汇总和原任务续跑。记录接收方实际回执，不能仅凭发出的 `@` 文本判定成功。
2. 验证数据授权失效后的基本状态、取消与停止等待，以及拒绝收尾、断线、重启、补权和明确重试；区分本地等待结束与远端停止。
3. 在 Windows 验证原生文件代理、命令、工具链及最终安装目录 ACL。macOS x64 未在本专项验收；macOS arm64 通过不能作为平台等价证明。
4. 指定真实项目完成安装依赖、构建、测试和回复，记录缓存、运行时、凭据、跨目录及出站边界。
5. 覆盖伪造机器人协议、跨群重放、未授权伙伴、新受众、越界路径、链接竞态、Plan/Review 写入、取消后重派、旧审批重放，以及撤权后的异步写回和外发。

## 后续能力与验收纪律

域名代理、内网/重定向限制、专用 Git/发布能力、固定成员受众策略和完整工具链兼容矩阵尚未作为本专项交付。网络仍是显式的通用出站开关。

执行真实测试前明确目标版本、设备及测试群；不改写现有真实授权来伪造验收。源码提交与推送不会自动更新两端正在运行的应用；发布与设备安装证据分别记录。Windows/macOS 打包、签名、公证、更新和回滚仍遵循根级工程合同。
