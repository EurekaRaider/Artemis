## 1. 审核结论

采用“composer 第四个入口 + 既有设计工作流产品化”的方向，保留 `workflow(code/design) × RunMode(plan/review/execute)` 的正交模型，继续使用 Pi 唯一循环、受限设计工具、不可变版本和独立预览宿主。

不能直接按原文逐项实现：现状描述部分过时，简报规格超出现有协议，自动修复缺少执行边界，版本对比和来源信息也包含尚不存在的能力。下面的调整作为本执行计划的实施口径；原调研与方案保留，便于追溯。

本次仅核对 Artemis 当前源码与四份输入文档；Open Design 内容作为历史调研参考，未重新审计其本地仓库或上游，不据此声明竞品现状、安全优劣或完整格式兼容性。

## 2. 范围与交付顺序

分两个产品里程碑交付：M1 是可靠、可发现的设计入口；M2 是简报、方向选择、检查修复、历史恢复和实施的完整闭环。阶段是本专项的新编号，不表示重新实施旧 design-p0/P3。

依赖链：`P0 → P1（M1）→ P2a → P2b → P2c（M2）→ P3 发布验收`。每阶段按下文验收独立提交，不把协议、界面、自动修复一次性堆在一个提交中。

v1 不包含：自由画布、任意框架编译、媒体生成、PDF/PPTX/ZIP 新导出、设备壳、内置品牌库、多评委、双实时预览与像素差异、IM 设计任务。保留已有静态 HTML 导出、有限静态结构编辑和 `/design` 入口。

## 3. P0：编辑可靠性与 UI 基线

**目标：先消除编辑丢失和权限歧义，再扩充入口。对应 B3/B6/B9。**

### 工作项

- [ ] 在现有 `design-panel-edits`、`design-panel-state`、`design-service` 测试中先补能失败的用例：编辑→撤销→丢弃→重做；全部撤销后丢弃；切任务/版本期间迟到响应；主进程草稿清除失败。
- [ ] 统一受控丢弃动作：确认目标草稿 key，清双层草稿，重置 patches/undone/operationId/颜色编辑合并状态；仅在清理成功后广播正确作用域的 cleared 事件。失败时显示错误并保留可恢复编辑，不把 UI 清空当成持久化成功。
- [ ] 检查并处理旧 `setDesignDraft` 写入迟到后复活草稿的竞态；必要时在现有通道增加顺序/代次校验，不创建全局草稿框架。
- [ ] 为所有编辑、撤销、重做入口增加一致守卫，含 macOS Cmd+Z、Windows Ctrl+Z 和 Shift 重做；输入框原生文本撤销不被面板抢走。
- [ ] i18n 归并到项目公共资源，覆盖 App 徽章、面板、禁用原因、空态、Dialog 与用户可见错误；用户生成内容不强行翻译。
- [ ] 以现有 `@artemis/ui` 组件和实际注册主题变量替换业务层裸控件；保留必要语义容器及受限拖拽结构。检查 Select 值唯一，不把“所有 DOM 都不能原生”当验收标准。
- [ ] 检查器按 B6 分组，优先 240px，窄面板需可收拢；沿用现有源编辑契约，校验数值区间、颜色、图片与结构目标。
- [ ] 队列按真实七态映射文案，完整保留 paused 与 needs-reconciliation；重排、取消、明确重交沿用后端能力。

### 验收门槛

1. 丢弃、切任务、保存失败、重启恢复均无草稿串写或复活；Plan/Review/busy 下所有编辑路径被拒绝。
2. en/zh-CN × light/dark 原生截图审查通过；英文界面无宿主中文残留；业务文案不出现 CAS 等术语。
3. 对话框打开时原生预览不覆盖弹层、不接收穿透点击；关闭后恢复正确预览可见性与焦点。
4. Tab 导航、可见键盘焦点、可访问名称和禁用原因可用；B0“无焦点光环”不解释为删除键盘焦点提示，动效支持减少动态效果偏好。

## 4. P1：模式入口与空态（M1）

**目标：不输入斜杠命令即可进入设计，且模式语义稳定。对应 B1/B2。**

### 状态决策

| 用户动作               | workflow / mode         | 约定                                                           |
| ---------------------- | ----------------------- | -------------------------------------------------------------- |
| 本地任务选“设计”       | design / execute        | 主进程确认后显示“设计”并开 tab；选择本身不生成内容             |
| 设计内选“计划”或“评审” | design / plan 或 review | 显示“设计 · 只读”，停止可执行预览                              |
| 设计内选“执行”         | design / execute        | 仍是设计；选择器显示组合状态“设计”，说明执行只作用于当前工作流 |
| 返回代码               | code / 原 mode          | 不擅自提升权限，处理现有未保存草稿离开流程                     |
| 点击“实施”并确认       | code / execute 请求     | 仅 Execute 可发起，经过不可变交接及既有队列                    |
| IM 或未绑定本地工作区  | 不变                    | 设计项禁用，提供原因                                           |

### 工作项

- [ ] UI 引入局部选择类型（RunMode 加组合入口），序列化仍只使用现有 workflow 和 RunMode，不传 `mode: design`。
- [ ] 模式与工作流的组合变更经可信主进程入口校验并一致返回；若现有两条调用无法原子完成，补一个组合动作，禁止先开放普通 Execute 再异步切 design 的中间发送窗口。
- [ ] 运行中切换只影响下一请求：不修改已经启动的工具集；不能立即切换时禁用入口并说明。重复点击、失败、切任务与工作区变化都不得留下虚假的选中态。
- [ ] 复用菜单组件能力呈现分隔、图标、简短说明与“用量较高”；直接以成功响应开面板，不等待 1.5 秒轮询。
- [ ] 徽章点击跳面板，菜单提供返回代码和队列入口；只读切换提示只出现一次。
- [ ] B2 六类意图与每类 2–3 条示例数据化并双语化；点击示例只填入 composer，不自动发送，不覆盖已有用户输入而无提示。
- [ ] 空态开始设计后聚焦 composer；无内容时不发空请求；已有请求时显示队列而不是重复引导。
- [ ] `/design` 保持原兼容语义，共享可用性检查和面板联动；不额外改变其在只读模式中的权限行为。

### 验收门槛

覆盖 workflow × 三种模式、无任务、IM、无工作区、运行中、失败、重启、快速切换任务。进入后可以生成并读取一个实际保存版本；生成过程中项目源码无修改。5 位试用者的“30 秒找到入口”和“正确说明设计只读”单独记录为人工结果，不以自动化代替。

## 5. P2a：同步与数据契约

**目标：为画廊、评审、历史提供真实、可重放的数据，先于循环自动化。**

- [ ] 设计持久事实继续使用版本化 envelope 与幂等 reducer；事件至少关联 thread、workspace binding、document、revision，以及稳定事件身份/顺序。预览实例状态可瞬态推送，不把每次布局 bounds 写入历史。
- [ ] 初次打开读取快照，再按顺序消费更新；订阅与快照衔接不得漏事件。断连/重启重新对齐快照；拒绝旧工作区、旧请求和重复事件。
- [ ] 替换 App/DesignPanel 两处定时轮询；临时兼容回退必须显式有限，不能让轮询和事件同时竞争覆盖新状态。
- [ ] 增加检查记录查询：按 document/revision/variant/page 精确绑定；区分未检查、检查中、通过、失败、不可用、取消。时间、动作数量等字段只在真实记录存在时展示。
- [ ] 检查问题可附 elementId；没有元素定位的错误仍能查看原始截图/错误说明。新增版本不能继承旧版本的“通过”徽标；一页通过不能代表整个方案通过。
- [ ] 历史列表补可选来源（AI/手动/恢复/未知）和恢复来源引用；需要请求摘要时沿已有身份关联读取，不复制完整 prompt。旧记录显示未知，不伪造作者。
- [ ] schema/存储演进需兼容旧库及旧事件；迁移失败保留原库并报告，禁止丢弃历史来“修复”解析。

**验收：**事件重复、乱序、丢失后重连、快速切任务、恢复旧数据均通过。记录事件到 UI 的 P95，≤200ms 是本地固定 fixture 目标；模型生成、冷启动原生预览和 vision 请求耗时单独报告，不能混作同一 SLA。

## 6. P2b：简报、品牌依据与方案画廊

**对应 B4/B7，依赖 P2a。**

### 简报

- [ ] 仅对影响结果的未决信息提问；当前请求已明确设备/用途/品牌时直接生成，已激活 DESIGN.md 不重复询问风格。
- [ ] 一张卡最多 3 题，每题 2–3 个选择且恰有一个推荐项，保留自由回答；稳定 questionId 与新增可选 optionId 在主进程验证唯一性和归属。
- [ ] 扩展 resolution 支持稳定选项 ID，保持旧 label 路径兼容；新路径不因切语言改变语义，不能靠 `[value: ...]` 文案约定绕过 schema。
- [ ] “使用推荐项开始”走正常确认/resolve 通道，验证当前待答问题后一次性提交全部推荐答案；倒计时行为沿用已有政策并明确显示，不另设静默批准机制。
- [ ] 简报结果写入版本 brief，后续修改以新请求迭代；首版不支持修改已完成工具调用的历史答案。中断、取消、重复提交、重启待答恢复纳入测试。

### 品牌与质量规则

- [ ] 项目根 DESIGN.md 和可选本地 tokens.css 通过现有允许的读取能力消费；当前用户要求优先，项目设计资料不得改变工具权限或沙箱限制。
- [ ] 定义输入预算、实际读取范围与依据记录；超预算提示按需分段读取，禁止截断后仍声称读全或 token 100% 溯源。缺失/解析失败如实说明，允许无品牌模式继续。
- [ ] 品牌变量与可编辑 `--design-*` 参数区分：需要微调时使用显式别名，不把品牌原名全部改写成设计参数。
- [ ] 最小 craft 规则只覆盖信息层级、排版、可读性、具体内容与可操作状态；服从用户风格要求，不硬禁用户明确要求的颜色或表现形式。
- [ ] 对照原方案 publication/stub guard：v1 检查占位内容与异常删页并展示诊断；不按文件缩小比例拒绝合法简化。现有 schema、静态所有权和 CAS 验证继续硬拒绝非法内容。

### 画廊

- [ ] 使用已有 variants.name/description 与精确版本检查截图形成方向卡，默认探索 3 个方向，小改可为 1 个，保持最多 6 方案 × 10 页。
- [ ] 未检查方案使用占位，生成中显示真实请求状态；不伪造缩略图或通过状态。多页卡片显示检查覆盖数与问题数。
- [ ] 卡片选择、方向键导航、继续修改和实施入口复用同一选择状态；含草稿时先处理草稿，失败不切走。

**验收：**充分简报不提问，使用推荐项能产出，en/zh-CN 回答 ID 一致，旧卡仍能回答；无品牌/大文件/有效 token/损坏输入都有用例；画廊显示与当前版本证据一致。

## 7. P2c：检查修复、历史与实施闭环（M2）

### 检查与自动修复（B8）

- [ ] 保存后复用 `design_preview_check` 检查相关页面，面板呈现真实结论、截图和动作数量；运行预览不等于已经检查。
- [ ] 首次检查失败后最多 2 次自动修复，每次保存新版本并复检；宿主记录本轮请求的计数、检查身份和关联 revision，限制不能只靠模型遵守提示词。
- [ ] 优先在同一 Pi turn 继续；确需续 turn 时复用既有持久队列，关联原请求且幂等，禁止渲染器订阅每次失败事件就自行追加请求。
- [ ] 修复启动前复核 execute/design、本地工作区、原请求仍有效且未取消。用户手动编辑、新请求改变方向、CAS 冲突或工作区变更时暂停交回用户，不能覆盖当前选择或草稿。
- [ ] “停止修复”使用现有取消与子执行结算边界；重启后不重放状态未知的请求。无 vision、超时、服务故障和取消与设计不通过区分，不消耗无意义的修复轮数循环。
- [ ] 两轮未过显示剩余问题并允许对话继续；未检查/失败不禁实施，但确认中保留状态，不称其为验证通过。

### 历史与恢复（B5）

- [ ] 时间线呈现父链、分叉、来源、当前与最新标志；首版源码对比和已有静态证据预览，不新增第二个活动预览实例。
- [ ] 恢复由可信面板动作读取指定不可变内容，以当前 head 为 baseRevision、全新 operationId 保存新版本并记录恢复来源；并发 head 变化走现有冲突语义，不自动覆盖。
- [ ] 恢复前处理草稿；达到 50 版本或 200MB 限额时明确拒绝并保留现状，不通过删历史完成恢复。
- [ ] 验证恢复后旧内容/父链仍可读；同一请求重试只产生一个结果；只读恢复被前后端拒绝。

### 实施交接（B10）

- [ ] 受控确认展示精确方案、明确页面集合、版本与检查状态；不默认为“全部页面”而实际只传当前页。
- [ ] 有草稿时前端拦截并定位处理入口；主进程再次核验。打开 Dialog 后 revision 改变不偷偷替换选择，失效时要求刷新。
- [ ] 确认使用稳定 requestId 和 DesignRef；同一提交重复点击/传输重试复用身份，显式重新实施创建新身份。
- [ ] 交接仍由既有队列完成，code turn 读取固定版本后实施；生成新设计不改变已交接引用；不得把 selection 退化成“最新版本”。
- [ ] 以既有 turn 变更清单展示结果，不承诺仅修改 UI 文件；工作区源码改动只发生在已确认实施的 Execute 请求中。

**验收：**失败→修复→复检、达到上限、取消、无 vision、重启待核对、并发冲突、容量不足、带草稿实施、重复确认及多页交接全部通过；至少一条真实模型链路完成生成→原生检查→微调→保存→实施→实际交互验证。

### 产品观察，不冒充自动验收
