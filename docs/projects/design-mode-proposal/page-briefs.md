# Artemis 设计模式 · 页面 Briefs

> **配套文档**：产品方案见 [solution.md](solution.md)。本文是页面/表面级规格：布局、元素、状态、交互、文案。
> **现状参照**：升级基于 `codex/design-p0` 的 DesignPanel（`apps/desktop/src/renderer/DesignPanel.tsx`）与 ComposerContextBar（`ComposerContextBar.tsx`），**增量演进，不推翻现有骨架**。
> **日期**：2026-09-12。

---

## 0. 全局设计约束（所有 brief 共同遵守）

1. **组件**：一律用 `@artemis/ui`（Button / Select / Dialog / TextField / 图标按钮等）。Select 的 options 值必须唯一、label 可辨识（历史崩溃前科）；Dialog 受控、可否决关闭；TextField 用 `inputRef` + `error` 传错。
2. **色彩**：只允许 `@artemis/theme-artemis` 语义令牌（`color.surface.*` / `color.accent.*` / `color.status.*`），全黑白灰体系，**不引入新色值、不回蓝**。通过/失败用 `color.status.success/danger` 语义令牌。
3. **排版**：14px 基准；胶囊文字小而轻、仅数字加粗；ID / 指令码（如 revision 前 8 位）无背板、等宽字体。
4. **图标按钮**：命中区 ≥28px；图标宁简勿闷；**删除/丢弃动作用垃圾桶图标**，不用 ✕。
5. **动效**：只用 `cubic-bezier(0.23,1,0.32,1)` ease-out；进入 200ms / 退出 140ms；无 scale(0) 起跳；**禁止 ease-in**。浮层（菜单/弹层/时间线）用毛玻璃质感（体系内 blur 令牌）。
6. **输入**：文本输入无聚焦光环（光标即焦点）；表单标签不换行；勾选/单选列表留白充足。
7. **文案**：大白话，忌术语。对用户只说"方案 / 版本 / 检查 / 实施"，不说 variant / revision / CAS / inspect。
8. **i18n**：所有新增字符串进 `shared/i18n-resources.ts`（en + zh-CN 同步补齐，typecheck 把关）；本文中文文案即 zh-CN 基准，英文随附。
9. **模式守卫**：Plan/Review（设计只读）下一切写入控件禁用且**附一句原因**；键盘快捷键同权守卫（修复现状）。
10. **布局纪律**：不移动设计面板之外的既有布局；面板内部升级保持"工具栏 → 提示区 → 草稿条 → 队列 → 画廊 → 画布+检查器"的既有纵向秩序。

## B1 · Composer 设计模式入口

**目的**：让不知道 `/design` 的用户一眼发现并一键进入设计（solution P1.1–1.3/1.5）。
**位置**：`ComposerContextBar` 的模式选择器（现有 计划/评审/执行 三项的 `CodexSelect<RunMode>`）。

### 布局

```
composer 顶条（现状）：
┌────────────────────────────────────────────────────────────┐
│ [项目 ▾]  [分支 ▾]        ……        [模式: 执行 ▾]          │
└────────────────────────────────────────────────────────────┘

点开模式菜单（升级后）：
┌──────────────────────────────────────┐
│ 模式                                  │
│ ○ 计划    先想清楚，只读              │
│ ○ 评审    只读，给修改建议            │
│ ● 执行    放开手脚写代码              │
│ ──────────────────────────────────── │   ← 分隔线（新分区）
│ ✦ 设计    进入设计面板，先出界面方案   │
│           再实施    ·  用量较高        │
└──────────────────────────────────────┘
（"✦ 设计"整项 hover 高亮；"用量较高"为小字胶囊，仅文字提示，不做进度条）

选中"设计"后：
┌────────────────────────────────────────────────────────────┐
│ [✦ 设计工作流]  [项目 ▾] [分支 ▾] ……   [模式: 设计 ▾]        │
│  ↑ 徽章：常驻左侧，点击跳设计面板；右侧 ⋯ 菜单含「返回代码」    │
└────────────────────────────────────────────────────────────┘
设计内切到 计划/评审 时，徽章变为：
│ [✦ 设计 · 只读]  …（切模式时 toast：「仍在设计里，现在只能看和聊。要写代码请点『返回代码』。」）
```

### 元素与状态

| 元素              | 状态                               | 说明                                                        |
| ----------------- | ---------------------------------- | ----------------------------------------------------------- |
| 菜单项"设计"      | 默认 / hover / 选中                | 选中后选择器触发器显示 ✦ + 「设计」                         |
| 菜单项"设计"      | **禁用**（IM 任务 / 无本地工作区） | 置灰 + tooltip「设计需要本地任务的工作区」；不可点          |
| 徽章"设计工作流"  | 设计激活                           | 点击 = 打开设计面板（已有能力）；菜单 = 返回代码 / 查看队列 |
| 徽章"设计 · 只读" | 设计 + plan/review                 | 同上；文案明示只读                                          |
| toast             | 模式切换提示                       | 3s 自动消失，可手动关                                       |

### 交互

1. 选中"设计"：`workflow=design + runMode=execute`（现有 contexts 通道），**自动打开**设计 tab（替代 1.5s 轮询自动发现，P2 事件化）。
2. 设计内选 计划/评审：只改 runMode，不退设计（现状语义），徽章+toast 澄清。
3. 「返回代码」：现有 DesignPanel 动作；徽章菜单内同款。
4. `/design` 命令保留（老用户路径），行为不变。

### 文案（zh-CN 基准 / en）

- 菜单项：「设计 — 进入设计面板，先出界面方案再实施 · 用量较高」/ "Design — Open the design panel: interface options first, then implement · Higher usage"
- toast：「已切换到{计划/评审}。还在设计里，只能看和聊；要写代码点『返回代码』。」/ "Switched to {Plan/Review}. Still in design (read-only). Click Return to code to edit."
- 禁用 tooltip：「设计需要本地任务的工作区。」/ "Design needs a local task workspace."

### 边界与错误

- 队列中已有设计请求时再发消息 → 现有入队逻辑，徽章菜单显示队列数。
- 视口极窄：菜单项说明小字可截断，保留标题。

### 验收

新用户（不知 `/design`）30 秒内从 composer 进入设计面板；设计内切模式后 5/5 用户能正确说出"还在设计里"；IM 任务中设计项禁用且有原因。

## B2 · 设计面板 · 空态

**目的**：把空面板从"一个按钮"变成"3 秒知道能做什么、怎么开口"（solution P1.4）。

### 布局

```
┌ design-panel（空态，居中卡片区，max-width 520px）──────────────┐
│                                                                │
│              ✦                                                  │
│        先看看界面，再动手写代码                                   │
│   描述你想要的页面或组件，我会给出几个不同的方案，                  │
│   你在预览里挑一个、改一改，满意了再实施。                         │
│                                                                │
│   想做什么？                                                     │
│   [网页原型] [移动原型] [组件] [着陆页] [后台界面] [先随便看看]     │
│    ↑ 意图 chips：单选；"先随便看看"= 不预设                       │
│                                                                │
│   试试这样说：                                                   │
│   · 给设置页做个深色主题的改版                    ← 点击填入      │
│   · 设计一个空状态插图页，配三句引导文案                           │
│   · 把这个表格改成卡片列表，给我两种风格                           │
│                                                                │
│   [ ✦ 开始设计 ]                                                │
│                                                                │
└────────────────────────────────────────────────────────────────┘
```

### 元素与状态

- 意图 chip 选中后：示例区换成该意图的 2-3 条示例（数据表驱动，i18n）。
- 「开始设计」：把意图+示例（或空）拼成一句话填入 composer（复用现有 `onConversation` 注入），焦点落到 composer。
- 队列里已有等待的设计请求时空态不出现（直接显示队列态）。

### 文案

- 标题：「先看看界面，再动手写代码」/ "See it before you code it"
- 按钮：「开始设计」/ "Start designing"；chip「先随便看看」/ "Just exploring"

### 验收

空态点击率（进入设计后 7 天内发出首个设计请求）≥ 60%；示例点击即填入无错位。

## B3 · 设计面板 · 整体框架（升级总览）

**目的**：定义升级后的面板秩序与组件替换范围（P0.3/0.4 落点），**不改变既有纵向骨架**。

### 布局

```
┌ design-panel ───────────────────────────────────────────────────────────┐
│ ① 工具栏                                                                 │
│ [设计文档 ▾][版本 ▾]        [返回代码]                    [✦ 新建设计]    │
│                                                                          │
│ ② 提示区（按需，最多一行+展开）                                            │
│    · 错误（status.danger） / 非执行模式只读（附原因）/ 非最新版本（可跳最新）│
│    · 冲突版本（说明 + 引导对比）                                           │
│                                                                          │
│ ③ 草稿条（有未保存编辑时出现）                                             │
│ [↶ 撤销][↷ 重做]   3 处未保存，已在本机留档    [保存为新版本] [🗑 丢弃]     │
│                                                                          │
│ ④ 任务队列（有排队时折叠条 + 数字角标）                                    │
│ ▸ 任务队列（2）                                            ← 点击展开 B9  │
│                                                                          │
│ ⑤ 方案画廊（B4）                                                          │
│ ┌────┐ ┌────┐ ┌────┐                                                    │
│ │ A  │ │ B  │ │ C  │   ← 方向卡：检查截图 + 名称 + 差异一句话 + 检查徽标    │
│ └────┘ └────┘ └────┘                                                    │
│                                                                          │
│ ⑥ 主体：画布 + 检查器（现有结构）                                          │
│ ┌───────────────────────────────────┐ ┌────────────────────────────┐   │
│ │ 画布（WebContentsView 预览占位）      │ │ 检查器 240px（B6）           │   │
│ │  页面: [首页 ▾]  [▶ 运行预览] [📷 检查]│ │ 选中元素 / 文字 / 颜色 /      │   │
│ │  [对比][源码|画布][导出 HTML] [实施]  │ │ 参数 / 数据绑定 / 依据       │   │
│ └───────────────────────────────────┘ └────────────────────────────┘   │
└──────────────────────────────────────────────────────────────────────────┘
```

### 升级要点（相对现状）

1. ① 工具栏从"原生 select 串"整理为两组：**身份组**（文档/版本）+ **动作组**（新建设计/返回代码）；动作组右侧对齐。
2. ③ 草稿条：数字加粗（"**3** 处未保存"）；「丢弃」换垃圾桶图标，点击弹受控确认（见 B6 边界）。
3. ④ 队列从 `<details>` 改为折叠条 + 角标（数字胶囊），默认收起。
4. ⑤ 画廊替代现有 240px 缩略条（详见 B4）。
5. ⑥ 检查器 210px → 240px（内容分组后需要），其余不动；预览仍是主进程 `WebContentsView` 覆盖矩形（机制不变）。
6. 全部控件换 `@artemis/ui`；全部文案进 i18n。

### 状态矩阵（简）

| 状态                | 表现                                                                         |
| ------------------- | ---------------------------------------------------------------------------- |
| 只读（plan/review） | ③⑥ 写入类控件禁用 + 顶部一句「现在只能看和聊；切到执行才能改。」；键盘同守卫 |
| 预览运行中          | ⑥ 画布工具条「停止」替换「运行预览」；画廊卡检查徽标转圈                     |
| 无 vision 模型      | 「📷 检查」禁用 + tooltip「当前模型不支持看图检查」；不阻塞其他功能          |

### 验收

en 截图零中文残留；组件契约测试通过；只读态下 Cmd+Z 无效果（回归）。

## B4 · 方案画廊（方向卡）

**目的**：把"变体缩略条"升级为可比较、可选择的方向卡（solution P2.2）。

### 布局

```
┌ 方案画廊（横向滚动，卡宽 ~180px）────────────────────────────────────┐
│ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐                  │
│ │ [检查截图] │ │ [检查截图] │ │ [占位纹样] │ │ [检查截图] │  ← 横向滚动     │
│ │──────────│ │──────────│ │──────────│ │──────────│                  │
│ │ 方案 A    │ │ 方案 B ●  │ │ 方案 C    │ │ 方案 D    │  ← ● 当前选中    │
│ │ 深色仪表风 │ │ 杂志编辑风 │ │ 还没检查   │ │ 极简留白  │                  │
│ │ ✓ 已通过  │ │ ✗ 2 处问题 │ │ （灰置灰） │ │ ○ 未检查  │                  │
│ └──────────┘ └──────────┘ └──────────┘ └──────────┘                  │
└──────────────────────────────────────────────────────────────────────┘
```

### 元素与状态

| 卡片状态                 | 视觉                                                |
| ------------------------ | --------------------------------------------------- |
| 当前选中                 | 边框 accent（近黑）、卡片轻微抬升（阴影令牌）       |
| 检查通过                 | 左下 `✓` 徽标（status.success）                     |
| 检查未通过               | `✗ n 处问题`（status.danger），点击滚到评审卡（B8） |
| 未检查 / 检查中 / 不可用 | `○ 未检查` / 转圈 / 灰（无 vision）                 |
| 生成中                   | 骨架卡 + 方案名占位                                 |

### 交互

1. 点卡片 = 切换画布到该方案（现有 variant 切换）；键盘 ←→ 在画廊内移动。
2. 卡片右键 / ⋯ 菜单：「就此方案继续改」「实施此方案」（复用现有动作）。
3. 名称与"差异一句话"来自 agent 生成内容（`designContent.variants[].description`），超出两行截断。

### 文案

- 画廊区标题（可选，仅首次显示）：「先挑一个方向」/ "Pick a direction"
- 徽标：「已通过 / n 处问题 / 未检查」/ "Passed / n issues / Not checked"

### 验收

画廊人均浏览方案数 ≥2；切换方案画布 ≤200ms 反映；≤6 卡横向滚动流畅。

## B5 · 版本时间线与对比

**目的**：把版本 select 升级为可理解的时间线（solution P2.4）；**恢复 = 写新版本**的语义在 UI 说清。

### 布局

```
点开工具栏「版本 ▾」→ 上弹时间线（毛玻璃浮层，max-height 60vh，内滚动）：
┌ 版本历史 ──────────────────────────────────────────┐
│                                                      │
│ ● 最新   今天 14:32   保存者：你（手动微调）      [预览]│ ← 当前
│ │                                                    │
│ ○ 今天 14:05   保存者：对话（你的要求：加深标题层级）│ ← hover 显 [对比][恢复]
│ │                                                    │
│ ○ 昨天 18:44   保存者：对话              ⚠ 有分叉    │
│ │                                                    │
│ ○ 昨天 18:02   保存者：对话                          │
│                                                      │
│ 说明：恢复不会覆盖历史，会存成一个新版本。             │
└──────────────────────────────────────────────────────┘
点「对比」→ 画布进入左右对比模式（复用现有源码对比能力的画布版）：
┌────────────────────────────┐
│ [所选版本]  │  [当前版本]    │
│  预览        │   预览         │
└────────────────────────────┘
（差异区域描边高亮；顶部提示条「正在对比 v14:05 与最新」+ [退出对比]）
```

### 元素与状态

- 条目：来源徽标（「你（手动微调）」/「对话」两态，来自 operations 表）+ 触发它的用户要求摘要（revision 关联的请求文本，超一行截断）；revision 前 8 位等宽小字、无背板。
- 冲突分支：`⚠ 有分叉` 小字徽标，点击展开分叉说明（现有 conflict 标志）。
- 「恢复」：受控确认 Dialog（「恢复到这个版本？会存成一个新版本，不会丢现在的。」[恢复][取消]）；恢复后 toast + 时间线新增条目置顶。
- 只读模式下「恢复」禁用。

### 文案

- 「版本历史」/ "Version history"；「恢复不会覆盖历史，会存成一个新版本。」/ "Restoring creates a new version; nothing is lost."

### 验收

恢复操作后历史零丢失（自动化回归：恢复前后版本条目只增不减）；对比模式退出回到原状态。

## B6 · 检查器（微调面板）· 打磨

**目的**：保持"受限微调"定位，解决信息密度与禁用原因问题（P0 组件化落点）。

### 布局（现有六类编辑分组化）

```
┌ 检查器 240px ─────────────────────────────┐
│ 选中：主要按钮 (data-design-id: hero-cta)   │ ← 等宽小字无背板
│ 源码行 128 · [查看源码]                     │
│──────────────────────────────────────────│
│ ▾ 文字                                     │
│   文案 [____________]                      │
│   颜色 [#000000]  圆角 [ 8 ] px            │
│ ▾ 图片                                     │
│   [替换图片…]（≤3MB png/jpg/webp）           │
│ ▾ 参数                                     │
│   圆角强度 --design-radius  [4─●────] 8px  │ ← min/max/unit 契约
│ ▾ 数据                                     │
│   标题 [____________]  ← data-design-bind  │
│ ▾ 结构                                     │
│   [移到静态容器 ▾]                           │
│ ▸ 页面结构（拖拽排序）                       │
│──────────────────────────────────────────│
│ ▾ 依据                                     │
│   设计依据 / 交互说明 / 参考了哪些文件        │
│ [通过对话修改]（带当前截图）                  │
└──────────────────────────────────────────┘
```

### 打磨点

1. 分组折叠（▾/▸），默认展开"文字/参数"，其余收起——现状是全部平铺。
2. 每个输入的即时校验镜像后端契约（数值 min/max、颜色 #RRGGBB、图片 ≤3MB 且自动转 PNG），错误走 TextField `error`，**提交前**就拦。
3. 只读模式：每组标题右侧统一灰字「只读」，输入禁用；不发 toast 轰炸。
4. 「通过对话修改」保留（拼上下文 + 截图附件走现有 action）——这是"受限编辑"的逃生门，文案明示「改不动的，让对话来」。

### 边界

- 未选中元素：检查器显示引导（「在预览里点一下要改的元素」）。
- 丢弃草稿（草稿条垃圾桶）：受控确认 Dialog「丢弃这 3 处未保存的修改？丢了就找不回来。」[丢弃][取消]；确认后**清撤销栈+重做栈+操作号+主进程草稿并广播事件**（bug 修复的 UI 面）。

### 验收

丢弃后重做按钮不可点（0 复活）；只读下所有输入与快捷键静默；分组折叠记忆用户选择。

## B7 · 设计简报卡（会话内）

**目的**：首个设计 turn 的结构化简报（solution P2.1），复用 Pi `request_user_input` 渲染，OD question-form 精神。

### 布局（会话流内，agent 消息卡）

```
┌ ✦ 先花 30 秒，把需求说清 ──────────────────────────┐
│                                                      │
│ 1. 这次主要做什么？                                    │
│   ◉ 整页界面   ○ 单个组件   ○ 改版现有页面   ○ 先看看   │ ← 单选，带推荐项
│ 2. 用在什么设备上？                                    │
│   ◉ 桌面浏览器   ○ 手机   ○ 两者都要                   │
│ 3. 风格有偏好吗？                                      │
│   ○ 跟随项目的 DESIGN.md（推荐） ○ 深色专业 ○ 轻快明亮  │
│   ○ 我另有参考（补充说明…）                            │
│ 4.（可选）还有什么必须满足的？                          │
│   [________________________________] ______           │
│                                                      │
│        [ 就这样，开始 ]   [ 跳过，直接开始 ]            │
└──────────────────────────────────────────────────────┘
提交后卡片折叠为一行摘要：
┌ ✦ 简报：整页界面 · 桌面 · 跟随 DESIGN.md ── (可点开修改) ┐
```

### 规则

- ≤5 题、每题带推荐默认；「跳过」= 全走默认直接开工（保证跳过也能出方案）。
- 答案以稳定枚举 id 回传（`[value: desktop]` 形式），不因文案本地化破坏 agent 分支。
- 同一设计文档只在首次请求时出现；后续迭代不再问。
- 卡片由 protocol 既有 user-input 事件渲染，**不新增 schema**；题目规范写在设计指令里。

### 验收

简报完成率 ≥70%、跳过 ≤30%；跳过路径同样产出方案；答案 id 稳定（日志抽查）。

## B8 · 检查评审卡

**目的**：让"agent 自己看过页面"可见化（solution P2.3）。

### 布局（面板内，画廊与画布之间按需插入；或会话内卡片）

```
通过时：
┌ ✓ 检查通过 ─ 今天 14:32 · 方案 B · 首页 ────────────┐

└──────────────────────────────────────────────────────┘
未通过时：

│   2. 第 2 屏在 1280 宽度下标题被截断                  │
│   [截图证据 ▾]                                        │
│   正在自动修复（第 1/2 轮）…            [停止修复]     │
└──────────────────────────────────────────────────────┘
两轮未通过：
┌ ⚠ 还有 1 处问题 ─────────────────────────────────────┐
│   「开始试用」按钮点了没反应。自动修复没搞定，           │
│   你可以在预览里点选它让对话修，或换个说法再试。         │
```

### 规则

- 触发：`design_preview_check` 完成即更新（P2 事件推送）；保存 revision 后按指令自动跑。

- 无 vision 模型 / 检查不可用：画廊与卡显示「○ 未检查」+ 一键重试，不阻塞保存与实施（**实施不因未检查而禁**，但列表里可见）。

### 验收

检查覆盖率 ≥90%；一次修复通过率 ≥50%；卡内每条结论都能跳到证据（截图或元素）。

## B9 · 任务队列（面板内折叠条展开态）

**目的**：等待中的设计请求可见、可管理（现状功能的信息架构化）。

### 布局

```
展开（面板 ④ 区，画布上方，max-height 40vh 内滚动）：
┌ 任务队列 ─────────────────────────────────────────┐
│ ▸ 任务队列（2）                              [收起] │
│ ┌────────────────────────────────────────────────┐ │
│ │ ① 做个深色主题的设置页改版                        │ │
│ │   等待中 · 前面还有 1 个       [↑ 提前] [取消]     │ │
│ ├────────────────────────────────────────────────┤ │
│ │ ② 设计空状态插图页                                │ │
│ │   失败 · 模型没有返回结果                          │ │
│ │   [已核对原任务，重新提交]  [取消]                  │ │
│ └────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────┘
```

### 规则

- 状态胶囊：等待中 / 进行中 / 已暂停 / 失败 / 待核对（重启后）——七态取用户可见五态文案。
- 「↑ 提前」每次只上移一格（现状约束，保留并在多次点击时提示「已经在最前面了」）。
- 「待核对」态解释一句：「应用重启过，这条需要你确认后才会重跑。」（对应 needs-reconciliation 绝不自动重放的既有语义）。
- 角标数字 = 等待+失败+待核对之和（进行中不计）。

### 验收

队列操作（提前/取消/重交）与现有 repository 状态机一一对应；无死键。

## B10 · 实施交接确认

**目的**：把「实施」从按钮直发升级为一次说清后果的确认（solution P2 闭环）。

### 布局（受控 Dialog）

```
┌ 把这个方案变成代码？ ────────────────────────────────┐
│                                                      │
│   方案 B · 杂志编辑风 · 全部 3 页                     │
│   版本 14:05（a3f19c02）· 不会被实施中的修改影响        │
│                                                      │
│   实施时我会：                                        │
│   · 精确读取这个版本的内容，按它来改代码                │
│   · 只改界面相关文件，改完给你一份变更清单              │
│                                                      │
│   ⚠ 有 3 处未保存的微调，先保存或丢弃才能实施。   ← 仅有草稿时
│                                                      │
│              [ 先不实施 ]    [ 开始实施 ]              │
└──────────────────────────────────────────────────────┘
```

### 规则

- Dialog 受控、可否决关闭（ESC/遮罩=取消）。
- 有未保存草稿：实施按钮禁用 + 顶部警示行 + 「去处理」链接跳草稿条（镜像现有服务端拒绝文案，**前端先行拦截**）。
- 确认后：退出设计工作流 → code turn 以固定模板引用不可变 selection（现有机制），会话首条消息卡片显示「✦ 正在实施方案 B（版本 14:05）」+ 完成后变更清单入口。

### 验收

带草稿点实施 0 次到达服务端（前端拦截）；实施引用的版本号与面板显示一致。
