# Computer Use 后续复现与验收

## #226：原始前台暂停报告

原始报告尚未稳定复现，不能关闭。报告未说明暂停时是否存在人工输入，不能把“完全没有人工输入”当作事实。

已经修复的“已释放浏览器的事件暂停后续原生控制”来自浏览器监听链路；原始 `User input during foreground control` 来自原生全局监听器，两者不能合并为同一根因。

## 复现输入

- 提报者的准确操作顺序、应用和助手版本、目标应用，以及首次暂停时是否有键鼠操作。
- 目标授权、前台许可、观察与控制租约的时间顺序，以及首次暂停事件的来源和诊断字段。
- 在允许访问的测试环境中分别检查真实人工输入、授权点击时序、注入事件回送和过期目标回调。工具禁止访问的应用不得通过其他通道绕过限制。

## 修复与验证约束

1. 找到稳定复现后，先加入能失败的回归，再作最小修改；没有证据时不增加忽略输入的时间窗口。
2. 真正人工接管必须立即停止后续输入；应用切换、目标释放、Stop、撤销、插件禁用、离开 Execute 和任务终止保持失效语义。
3. 前一目标、租约、轮次或助手的延迟回调不得影响新控制；自身注入与人工输入按实际事件证据区分，不能只凭时间猜测。
4. 验证有效许可跨轮复用、撤销时异步签发拒绝、后台边界及高风险下限。任务授权只属于当前父任务及可信内置 Computer Use，不扩大用户请求。
5. 使用同一版本和脚本保存结构化原生证据，分别报告真实用户接管、真实模型延迟及所声明平台最终包的签名/公证范围。

关闭原始报告前必须取得与该场景对应的原生证据；单元测试、另一个监听链路的修复或合成夹具通过均不能替代。
