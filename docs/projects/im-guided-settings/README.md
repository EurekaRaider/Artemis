# 消息接入：引导式设置交互提案

日期：2026-09-13。状态：提案，尚未按此方案实施。范围：以当前生产实现为依据，重新组织首次设置、后续管理和异常恢复；原型的旧字段与演示状态不作为业务依据。

## 1. 建议结论

将当前六步指引与分散的管理页面，组织成「五步首次设置 + 完成后的连接概览 + 独立群协作引导」。每步在同一位置容纳操作说明、所需参数、执行结果、错误恢复和下一步；用户无需在“指引”和“实际设置”之间往返。

首次路径：连接这台电脑 → 接入机器人 → 确认你的账号 → 选择项目与访问范围 → 发送测试任务。

设计重点不是减少必须确认的权限，而是减少不需要用户理解的技术参数。设备注册随服务启动自动完成；平台身份尽量自动识别；数据与分享范围必须显式确认。

## 2. 实际实现：步骤、参数与关联

### 2.1 准备服务与注册设备

当前指引将二者列为两步，个人模式实际由一次 `setup-local` 完成。

| 参数/结果            | 个人内置服务           | 团队服务                                            | 关系与限制                                                     |
| -------------------- | ---------------------- | --------------------------------------------------- | -------------------------------------------------------------- |
| 服务方式             | 一键启动内置 Gateway   | 连接已有 Gateway；可另外导出独立部署包              | 用户任务最终在注册的电脑上执行                                 |
| `gatewayUrl`         | 系统生成               | 填管理员提供的服务地址，界面指引为 HTTPS 域名与端口 | 不填 `/health` 或其他路径；换服务需重新注册                    |
| `deviceName`         | 当前配置；默认 Artemis | 用户可填易识别的设备名                              | 协作中用于辨认执行电脑                                         |
| `adminToken`         | 内置服务管理           | 管理员输入                                          | 注册操作清空，不作为本地持久配置；团队后续管理操作可能再次需要 |
| `deviceId`、设备凭据 | 自动注册产生           | 注册成功产生                                        | 展示只读结果，不让用户手工编造或编辑                           |
| `enabled`            | 独立于“服务已启动”     | 同左                                                | 暂停保留配置；启用时不能修改团队地址或再次注册                 |

服务随 Artemis 启停。远程接收任务要求电脑唤醒、应用运行。团队 Gateway 在线不等于本机可执行任务。独立部署、HTTPS 域名和运行包属于管理员支线，不应要求个人用户先学会。

### 2.2 连接机器人

共同参数：`channel`；可选 `id`、`name`。连接 ID 可自动产生，名称可默认平台名。已有连接应按连接 ID 单独管理。换密钥与换机器人不是同一动作：平台、企业或机器人身份变化需要新连接 ID，不能继承旧连接的绑定身份。

| 平台        | 首屏必填                                 | 默认/自动获取                                                                                         | 条件参数                                                                                                         | 外部步骤及依赖                                                                                                                                                       |
| ----------- | ---------------------------------------- | ----------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 飞书 / Lark | `appId`、`appSecret`                     | 新连接默认 `transport=websocket`；`tenantId`、`botOpenId` 可留空自动获取；区域为 `domain=feishu/lark` | `transport=webhook` 时额外填写 `verificationToken`、`encryptKey`；需要公网团队服务；保存后读取真实 `callbackUrl` | 创建自建应用、添加机器人、开权限；长连接需先在 Artemis 保存建立连接，再去平台选择长连接接收、订阅 `im.message.receive_v1` 并发布；审批卡片还需 `card.action.trigger` |
| 企业微信    | `tenantId`（Corp ID）、`botId`、`secret` | 长连接，无需公网域名                                                                                  | 可选连接 ID、名称                                                                                                | 创建“智能机器人 / API 模式”，选长连接，复制 Bot ID / Secret，配置可使用成员；同一 Bot ID 只连接一份服务                                                              |
| Slack       | `botToken`（xoxb-）、`appToken`（xapp-） | Socket Mode；工作区、应用、机器人身份自动识别                                                         | 可选连接 ID、名称                                                                                                | 导入内置 Manifest、安装到工作区、取得 Bot Token；App-Level Token 需 `connections:write`；两个 Token 必须来自同一应用                                                 |

团队服务保存机器人时，还需 Gateway 管理凭据；个人内置服务不显示该字段。机器人密钥在对应 Gateway 加密保存，不能一律说“保存在这台电脑”。

Slack Manifest 已包含 `chat:write`、`im:history`、`app_mentions:read`、`files:read`、`users:read`，事件为 `message.im`、`app_mention`。不用让用户逐项手抄。

**状态必须区分：**未配置 → 保存中 → 凭据已保存/连接中 → 已连接；失败可能来自凭据、权限、身份不匹配或网络。成功保存不代表机器人已经能收到用户消息；“已连接”也不证明飞书事件已发布。

### 2.3 绑定自己的账号

| 参数/状态                              | 谁提供                         | 逻辑关系                                               |
| -------------------------------------- | ------------------------------ | ------------------------------------------------------ |
| 平台/连接                              | 从当前机器人继承；多连接时选择 | 不让用户在下一步再次猜平台；Slack 使用无斜杠指令       |
| 一次性配对码、`expiresAt`              | `pair` 生成，最多 300 秒       | 新码清除旧待确认请求；过期禁用复制，需重新生成         |
| `requireConfirmation=true`             | 设置流程固定                   | 收到请求后在桌面核对本人身份并批准，不能复制后自动绑定 |
| `request.id`、平台身份、`connectionId` | 收到真实私聊后返回             | 用于核对和批准/拒绝，不要求用户输入 user ID            |
| 已绑定身份                             | 批准并刷新后返回               | 平台身份绑定设备；解除旧绑定是换设备的重要支线         |

私聊发送：企业微信、飞书 `/pair CODE`；Slack `pair CODE`。配对在连接未启用时也能刷新，不应为了配对提前开放项目执行。

### 2.4 项目、数据与操作权限

这是当前最复杂、也不能被“简化掉”的步骤。仅勾选项目不是完整授权。

| 参数                                            | 实际默认/范围                            | 关系                                                               |
| ----------------------------------------------- | ---------------------------------------- | ------------------------------------------------------------------ |
| `projectId`                                     | 桌面已打开的项目；最多 100 个 grant      | 无项目先去打开；不能授权不存在的项目                               |
| `defaultProjectId`                              | 首次勾选项目自动设定；也可“每次明确选择” | 必须来自授权项目；取消默认项目后不能继续引用它                     |
| `mode`                                          | `plan` 默认；另有 `review`、`execute`    | Plan/Review 在执行器前禁止写入                                     |
| `approval`                                      | `ask` 默认；另有 `automatic`             | 自动执行仍受已授权范围约束，不代表完整本机权限                     |
| `shell`                                         | 默认 false                               | 仅 Execute 可选；取决于本机受限命令能力                            |
| `network`                                       | 默认 false                               | 界面要求 Execute 且 shell 开启；当前是通用命令联网，不是域名白名单 |
| `expiresAt`                                     | 新 grant 默认 30 天；手动续期 30 天      | 当前没有任意日期表单或自动续期配置                                 |
| `tokenBudget`                                   | 协议默认 100000；1024–1000000            | 当前面板未提供输入控件；提案保留默认，不另造首次必填项             |
| `groups`                                        | 默认空；选择协作空间                     | 首次单聊无需配置；加入群空间不会自动授权项目                       |
| `security.scopes[].audience`                    | `owner` 或所选 `space:<id>`              | 每个分享对象有独立数据范围                                         |
| `readPaths`、`writePaths`                       | 从目录/文件树显式选择                    | 可写必须是可读子集；受保护文件不能选；选目录包含未来内容           |
| `filePaths`                                     | 系统记录明确文件                         | 防止文件被替换成目录后扩大范围，不显示技术字段                     |
| `confirmedAt`、授权 `revision`、`spaceRevision` | 用户确认后由系统维护                     | 修改范围会取消确认；群成员/端点修订变化需要重新确认对应受众        |

数据范围允许内容参与发给对应会话全部成员的自动回复，因此“可读取”与“可分享给谁”必须放在一起。撤销授权会停止相关远程工作；范围变更会使旧修订失效。凭据文件与执行控制文件始终保护；远程入口不开放完整桌面 shell、MCP 或扩展。

当前实际操作为“保存项目授权”，再用顶部开关启用，二者不是现成的原子操作。提案可提供一个用户入口，但必须按保存成功→启用执行，并呈现部分成功。

### 2.5 第一条任务

当前实现只提供操作指引：发送 `projects` 看授权项目，发送 `new 请查看当前项目，告诉我它是做什么的，先不要修改文件。`，再用 `status` 看进度；飞书/企微指令加 `/`。

成功证据：IM 返回任务编号、桌面出现同一个 IM 来源任务、任务完成且 IM 收到回复。当前 `ImSetupGuide` 的这一项 `done` 固定为 false，尚无“首次测试完成”的专门持久字段，不能把现有行为描述为自动验收。

### 2.6 可选群协作

完整依赖：同一 Gateway 上的机器人和参与设备 → 各账号先配对 → 各群内 @机器人发 help 发现群 → 选群、成员和确认人 → 保存空间 → 每个群确认 → 每位成员给空间授权项目和数据范围 → 进入群任务。

| 参数                              | 来源/限制                                                                       |
| --------------------------------- | ------------------------------------------------------------------------------- |
| `id`、`name`                      | 空间 ID 自动生成，用户填写易识别名称                                            |
| `endpoints`                       | 从已发现群/频道选择；包含 connectionId、会话 ID、kind=group；最多 8 个          |
| `participants`                    | 从已配对账号与设备选择；含 deviceId、identity、name；最多 50 人，显示名不能为空 |
| `administrators`                  | 每个接入连接选择相应参与成员作为确认人                                          |
| `spaceConfirmation`               | 保存后给出 `/space-confirm <spaceId>`；Slack 去掉 `/`                           |
| 确认进度与 revision               | 按群确认；修改群或成员后重新确认                                                |
| 各项目 `groups` 与 security scope | 各成员在自己的电脑授权，不能由空间管理员代开全部项目                            |

发现群≠空间已保存≠各群已确认≠项目已授权。任何一项未完成，都不能显示“全部就绪”。高级 JSON 与表单是同一份草稿；JSON 无效时应先修正或清空恢复表单。

### 2.7 后续管理能力归属

- 机器人：新增连接、更换凭据、查看健康、删除连接；飞书旧版迁移为独立入口，重新配对与授权，不导入旧绑定。
- 账号：待确认请求、批准/拒绝、解除绑定。
- 项目：修改范围、续期、撤销；待审外发结果、私人任务交接属于运行管理，移出首次设置正文。
- 群空间：修改/删除空间、成员管理、打开协作对话；删除空间保留平台原生群和历史。
- 服务：暂停/恢复、设备详情、团队重新注册、导出独立包、诊断。

## 3. 现状为什么让小白困惑

1. 六步指南点进去是渠道/通用管理页；用户要记住自己在哪一步，再寻找下一步。
2. 个人一键操作被拆成“准备 Gateway”“注册电脑”两步，看起来比实际复杂。
3. 当前管理就绪条件主要是“有已连接机器人 + 有身份”，没有覆盖项目数据范围和首条任务结果，容易过早离开引导。
4. 顶部开关只检查设备与机器人等前置条件，不能用开关已开启代替“能安全完成任务”。
5. 飞书配置有明确先后顺序：先建立长连接，再回平台订阅发布；把全部说明放在折叠教程里容易漏掉。
6. 授权页混合文件、受众、模式、审批、命令、联网、群与续期；不同使用阶段的信息同时出现。
7. 草稿、已保存配置、当前连接健康、设备运行状态没有始终分层表达；断网刷新失败也不应直接解释成密钥坏了。

## 4. 推荐交互：五步首次设置

### 页面骨架

保留当前设置弹窗与灰阶圆角语言。顶部只保留标题、简短说明和“设置进度 2/5”；首次状态暂不放总开关。

紧凑步骤轨道在上方；当前步骤显示完整卡片，已完成步骤压缩为一行摘要并可“编辑”，未来步骤显示名称与前置提示。卡片结构固定：本步目的 → 需要操作的内容 → 状态/问题 → 底部动作。

不要在向导里面再套“平台侧栏 + 通用侧栏”。卡片底部固定一个主操作，配“上一步”或“稍后继续”；返回已完成步骤保留草稿。所有常用动作使用共享图标加明确动词。

### 第一步：连接这台电脑

标题“让这台电脑接收消息”。默认选“个人使用”，主按钮“启动并连接”；“使用团队服务”是同卡次级分支，展开后显示地址、设备名、管理凭据。

启动时显示“启动服务 → 注册电脑”的状态，不让用户执行两遍。完成摘要：“这台 Mac 已连接 · 本机服务”。团队已有机器人时下一步直接展示可选机器人，跳过新建凭据。

失败留在本步：端口占用/注册失败分别给出原因与重试；禁止双击重复注册。已连接后切换服务先暂停并明确确认影响。

### 第二步：接入机器人

先选择“飞书 / Lark”“企业微信”“Slack”，飞书国内/国际在同卡选择；只展开当前平台。

本步骤内使用三个紧凑子阶段：**准备机器人 → 填写凭据并连接 → 完成平台接收设置**。

- 飞书：两项凭据首屏可见；高级收纳自动身份与连接方式。连接后直接在此卡出现“回飞书开启长连接、订阅并发布”的下一项。平台侧步骤由用户确认已完成，并标注“收发将在后续配对验证”，不伪装成系统检测。
- 企微：创建智能机器人路径与三项凭据同屏，不出现 Agent ID、应用 Secret、HTTPS 回调等旧原型选项。
- Slack：先给“复制应用配置”“打开应用管理”，再给两项 Token；安装与获取 Token 的说明紧邻对应字段。
- 团队已有连接：选机器人并查看状态即可，新增或更换配置才要求管理员凭据。

系统能自动识别的团队/机器人信息显示为确认摘要。填错定位具体字段；权限缺失定位对应平台步骤；连通中不显示成功。主按钮随阶段为“连接机器人”“已完成平台设置，继续”。

### 第三步：确认你的账号

标题“只允许你的账号使用这台电脑”。继承上一步平台和机器人，不要求重新选。

突出一条完整可复制指令、剩余有效时间与“打开机器人单聊”的文字指引。状态顺序：未生成 → 等待你发送 → 收到账号请求 → 待本人确认 → 已绑定。

收到请求原位替换等待区，展示平台、机器人和可验证的账号 ID；有真实名称时再显示名称，不能编造昵称。两个动作：“确认是我”“拒绝”。成功摘要“账号 … 已绑定到这台电脑”。

“复制指令”只复制，不代表已发送。无请求时给“检查接收设置”“刷新结果”；过期直接“生成新指令”。自动刷新不能打断手工核对或修改。

### 第四步：允许访问哪些项目和文件

默认个人单聊，按三件事组织，而不是铺开技术字段：

1. **选择项目**：默认只引导一个项目；勾选后在该项目内立即出现范围配置。没有项目给“打开项目”。
2. **选择能做什么、能看什么**：默认“只读分析（Plan）”；另有“只读审查（Review）”“允许修改（Execute）”。文件树与可读/可写列同处，不自动全选；可写依赖可读。用户选择权限档后显示“回复仅发给你的单聊”。
3. **确认并启用**：展示项目、文件范围、回复对象、模式、有效期摘要，用户确认后“保存并启用”。

命令与网络仅在 Execute 下展开；审批默认每次确认。群授权在尚未建群时收起，Token 预算继续使用现有默认。多项目时才强调默认项目，并允许“每次明确选择”。

“保存并启用”按两阶段执行：授权保存失败则不启用；保存成功、启用失败则明确“授权已保存，连接未启用”，只提供“重试启用”。不能因为按钮文案合并就假设后端原子成功。

### 第五步：发一条测试任务

显示一条只读 `new` 指令供用户发到已配对单聊，另外折叠提供“查看项目”“查看状态”。不让用户连续读三大段教程才开始。

可观测进度建议为“收到消息 → 桌面出现任务 → 任务完成 → IM 回复已送达”。其中前几项可研究复用现有任务与诊断状态；必须核对当前账号、连接、项目与本次设置时间，不能拿历史任务充当证据。现有代码缺乏完整自动验收，需要新增关联逻辑。

在该逻辑实现前，使用诚实版本：“打开测试任务”与“我已收到回复”；后者只标记“用户确认”，不显示“系统验证通过”。复制不能代替发送，模型不可用不能归类为机器人连接失败。

完成后进入连接概览；提供“开始使用”“设置群协作（可选）”。

## 5. 完成后的管理模式

概览展示“飞书机器人 → 我的账号 → 这台电脑 → 已授权项目”，另列当前运行状态。配置是否完整、服务是否健康、测试是否通过分开表达。

| 分区     | 摘要与同区操作                                       |
| -------- | ---------------------------------------------------- |
| 消息服务 | 本机/团队、设备、在线状态；暂停/恢复、团队配置、诊断 |
| 机器人   | 按连接显示名称/平台/健康；添加、更换凭据、修复、删除 |
| 我的账号 | 已绑定账号与待确认请求；绑定另一个账号、解除         |
| 项目访问 | 项目、模式、文件与受众、有效期；编辑范围、续期、撤销 |
| 群协作   | 空间、群数、确认进度、授权情况；独立引导与管理       |

再次打开不重跑整套流程。有问题定位对应分区；“继续设置”回到最早缺少的有效条件。某个备用机器人失败显示“部分连接异常”，不把仍可用的连接全部标成不可用。

## 6. 群协作的独立引导

在同一面板开第二条流程，顶部提供返回单聊设置：

1. **发现群**：沿用已连机器人；按平台提供带正确斜杠规则的指令。结果列出已发现群。
2. **选择群与成员**：空间名称、群入口、账号与电脑、各连接确认人都在本步；未发现群/未配对成员提供返回对应步骤，不给空 JSON。
3. **各群确认**：按群显示“待确认/已确认”，每行有正确完整指令；不可将一条确认当作所有群完成。
4. **授权我的项目**：在此流程内调用同一项目权限组件，受众预选当前空间，但不自动勾选文件、不代替其他成员授权。自己的授权与其他成员是否可用分开展示。

共享状态必须明确：“已保存，等待 2 个群确认”“群已确认，尚未授权项目”“你的项目已就绪”。更改参与人/群时重新确认，并提示既有授权可能需更新。

## 7. 异常、草稿与交互结果

| 场景                 | 界面反馈                                      | 恢复与保留                                  |
| -------------------- | --------------------------------------------- | ------------------------------------------- |
| 加载失败             | 无法获取设置；不伪装成首次空态                | 重试；不覆盖已有配置                        |
| 本机服务启动失败     | 本步保留，显示具体原因                        | 重试启动；无重复请求                        |
| 团队注册失败         | 地址或凭据错误定位字段                        | 保留非敏感输入；按真实策略重新输入管理凭据  |
| 凭据已存但机器人未连 | “已保存，连接中/连接失败”                     | 同卡诊断、重试、更换密钥                    |
| 自动识别失败         | 说明缺少哪项身份/权限                         | 只展开对应高级字段或补权限步骤              |
| 状态刷新失败         | “暂时无法确认状态”，保留上次更新时间          | 重试；不误判凭据失效                        |
| 配对码过期/请求拒绝  | 本步保持未完成                                | 新码；拒绝不创建账号                        |
| 权限未确认/已过期    | 明确缺少文件范围或续期                        | 本区修改；保存后才生效                      |
| 保存失败             | 草稿与已保存摘要区分                          | 保留草稿，可重试或放弃                      |
| 保存成功、启用失败   | “权限已保存，未启用”                          | 仅重试启用                                  |
| 运行时断网/电脑离线  | 配置完成仍保留；当前不可接任务                | 恢复服务，不重复填写全部参数                |
| 撤销项目/解绑/删连接 | 展示对象及影响                                | 明确确认；失败不提前删行                    |
| 离开未保存步骤       | 同一步内返回/折叠保留；离开流程提示保存或放弃 | 密钥只在页面内存，不放 URL 或浏览器持久存储 |
| 重试后迟到响应       | 不覆盖新状态                                  | 操作版本/取消标志、按钮防重复提交           |

确认只用于身份核对、数据范围与权限扩大、撤销/删除、重新注册、丢弃输入等有实际影响的操作；不为普通下一步连续弹确认。

## 8. 原型需要覆盖的验收范围

- 三平台首次成功流程；团队已配机器人跳过凭据；飞书 HTTPS 条件分支。
- 个人一键启动、团队注册失败重试、服务运行中断与恢复。
- 必填错误、密钥显隐、自动识别失败、连接中、权限不足、网络失败、单连接修复不改变其他连接。
- 配对成功/拒绝/过期/重复请求/换码；核对身份后才完成。
- 项目为空、多项目、默认项目撤销、文件范围未确认、Plan/Review 写入禁止、Execute 命令与网络依赖、授权到期、保存失败及部分成功。
- 测试任务收到/排队/模型失败/完成/回复失败；区分配置成功与端到端成功。
- 群发现、成员为空、保存前校验、部分群确认、缺少个人授权、成员变化后重新确认。
- 所有按钮真实改变相应状态；演示控制与用户设置分离；不把真实密钥写进示例或存储。
- 鼠标和键盘、窄屏、浅色/深色、reduced-motion；错误反馈不移动操作按钮；对话框聚焦与返回正确。
