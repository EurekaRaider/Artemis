# docs/ 文档管理规则

本文件约束正式文档与资产的放置、命名和清理。工程纪律见根级 [AGENTS.md](../AGENTS.md)，文档入口见 [README.md](README.md)。

## 目录结构

```text
docs/
├── AGENTS.md        # 文档规则
├── README.md        # 导读
├── architecture.md # 系统架构
├── install.md      # 安装说明
├── guides/         # 当前使用、开发与维护指南
├── assets/         # 图片、图源与截图清单
└── records/        # 持续维护的必要记录
```

## 放置规则

- 总体架构和安装说明留在根级；其他正式说明放入 `guides/`，使用清楚的主题文件名，例如 `hooks.md`、`hooks-en.md`。单篇文档不建立子目录；仅在一个主题确实需要多份配套文件时考虑分组。
- `guides/` 描述当前能力、操作、开发契约和实际限制，不收纳未实施方案或阶段流水账。
- 已有完整 UI 引导的用户操作不另写独立手册；配置、授权和接入步骤由产品界面维护，避免两套说明重复和过时。
- `records/` 只保留需要持续维护的发布说明、CI 约定及资产规范。更新现有文件，不堆积历史副本。`records/release-notes.md` 由 Release 工作流直接读取，调整路径必须同步工作流。
- 图片及其 HTML/SVG 图源统一放入 `assets/`，同一张图使用相同文件名。界面截图放入 `assets/screenshots/`，与 manifest 中的文件名、尺寸和摘要保持一致。
- 文档配套脚本放到根级 `scripts/`；可运行示例放到根级 `examples/`。
- 原型工程位于根级 `prototypes/`，由其 [README](../prototypes/README.md) 管理。迁移或修改前后运行组件检查，保留冻结基线的可追溯性，不通过重写摘要掩盖已有差异。
- 进行中的方案放到根级 `plans/<topic>/`。验收完成后删除专项过程材料，必要的长期结论并入正式指南；Git 历史负责追溯。外部参考原文优先使用固定来源链接，不复制整套文档树。

## 命名与索引

- 文件名使用英文 kebab-case；英文版本使用 `-en.md` 后缀，正文语言按目标读者选择。
- 跨文档引用使用相对路径；外部来源使用可追溯链接。新增正式文档在 [README.md](README.md) 登记。
- 不在 `docs/` 放临时笔记、原型源码、构建输出、整套外部规格或一次性验收报告；临时结果放 `/tmp` 或 Git 忽略的 `artifacts/`。

## 清理与迁移

1. 用 `rg` 核对文档、源码、脚本、测试、CI 和 manifest 的引用。
2. 确认内容已被取代或用户已确认验收完成；不要仅凭日期判断。
3. 删除跟踪文件使用 `git rm`。保护未跟踪文件及现有未提交修改；授权迁移时保留内容，只调整必要的路径引用。
4. 同步索引、脚本的仓库根定位、测试与清单路径；验证本地链接和受影响的检查。
5. `.DS_Store` 等本地产物不入库；发现即清理。

目录规则必须与实际结构一起维护，避免重新引入空分类、单文档目录和过期材料。
